### 시뮬레이션 개요
```
제목: "커스텀 악성코드 제작 시뮬레이션"
총 7스텝, 4개 페이즈
공격자(해커) 시점 + 방어자(SOC) 시점 동시 제공
```

### 4 Phases × 7 Steps
```
Phase 1: 🔧 페이로드 생성 (Step 0-1)
  Step 0: msfvenom → Meterpreter 리버스 HTTPS 페이로드 (510바이트)
  Step 1: crypter.py → AES-256 암호화 + 안티디버깅/샌드박스

Phase 2: ⚡ 로더/RAT 제작 (Step 2-3)
  Step 2: gcc → 프로세스 할로잉 로더 컴파일 (48KB)
  Step 3: rat_builder.py → 모듈식 RAT (키로거/스크린샷/유출/지속성)

Phase 3: 🛡️ 탐지 우회 (Step 4-5)
  Step 4: evasion_test.py → 4개 AV/EDR 우회 테스트 (Defender/Kaspersky/CrowdStrike/SentinelOne)
  Step 5: dropper_builder.py → 엑셀 DDE 드롭퍼 (재무보고서 위장)

Phase 4: ✅ C2 인프라 가동 (Step 6)
  Step 6: c2_server.py → WebSocket + 도메인 프론팅 C2 서버 시작
```

### 각 스텝의 3-Layer 설명 체계
```
Layer 1: feynman (파인만)
  → 비전공자도 이해할 수 있는 일상 비유
  → 예: "크립터는 악성 코드의 '변장 도구'입니다"

Layer 2: desc (기본)
  → 1-2문장 요약. 무엇을 하는지 + 왜 하는지
  → 예: "AES-256 암호화와 안티디버깅/안티샌드박스 기법으로 페이로드를 래핑하여 탐지를 우회합니다"

Layer 3: expert (전문가)
  → 정확한 기술 명세. API명, 수치, 프로토콜 포함
  → 예: "AES-256-CBC 암호화와 PBKDF2 키 도출(10만 반복)로 정적 분석을 무력화합니다"
```

```
각 스텝마다:
  해커 시점: cmd + out + hackerLog (공격 기법)
  방어자 시점: def + defAction + defTooltip (탐지/대응)

예시 (Step 4: AV/EDR 우회 테스트):
  해커: "4개 백신 모두 우회 성공! CrowdStrike는 간접 시스콜로 우회"
  방어: "EDR 벤더: 다중 EDR 제품에 대한 조직적 우회 테스트가 감지"
        "Action: 새로운 행위 시그니처가 모든 엔드포인트에 배포됨"
```

### 네트워크 토폴로지 (topoNodes + topoEdges)

## 7. 시나리오 설계 기준 (Design Principles)

### 콘텐츠 작성 원칙
| 원칙 | 설명 | 적용 예시 |
|------|------|----------|
| **파인만 기법** | 복잡한 개념을 5살도 이해할 비유로 | "크립터 = 악성코드의 변장 도구" |
| **3-Layer 깊이** | feynman(비유) → desc(요약) → expert(정밀) | 모든 랩 스텝 3개 설명 병렬 |
| **공격↔방어 이중** | 해커 기법마다 방어자 탐지/대응 매칭 | Step마다 cmd+def 쌍 |
| **나선형 반복** | 같은 주제를 깊이 달리하여 레벨마다 | beginner(개념) → intermediate(실무) → advanced(커널) |
| **인터랙티브** | 수동적 읽기 최소화, 능동적 참여 | 매칭 게임, 순서 배열, RPG 탐색, 퍼즐 |
| **실제 도구 기반** | 교육용 가상 도구 대신 실제 보안 도구명 | msfvenom, CrowdStrike, YARA, VirusTotal |
| **용어 즉시 해설** | 전문 용어 등장 시 즉시 terms 배열로 해설 | 각 랩 스텝에 terms: [{ name, desc }] |

### 랩 시나리오 JSON 작성 기준
```
1. 스텝 수: 5-12개 (너무 짧으면 몰입 X, 너무 길면 이탈)
2. 페이즈: 3-5개 (MITRE ATT&CK 킬 체인 기반 구분)
3. stepDuration: 8초 기본 (TTS + 터미널 출력 타이핑 시간 고려)
4. cmd: 실제 실행 가능한 형태의 명령어 (교육적 정확성)
5. out: 현실적인 출력 (실제 도구 출력 형식 참고)
6. feynman: 3문장 이내, 비유 필수
7. expert: 정확한 API명, 프로토콜, 수치 포함
8. terms: 스텝당 2개 이내 (용어 과부하 방지)
9. hackerLog.lines: 3개 (핵심 로그만 선별)
10. defTooltip: 이모지 + 1문장 (빠른 스캔용)
```

### 그래픽 슬라이드 작성 기준
```
1. 슬라이드 수: 15-25개 (5분~10분 자동재생)
2. 자막: 1슬라이드 = 1핵심 메시지 (문장 1-2개)
3. 시각 요소: FontAwesome 아이콘 90px+, 카드 UI
4. 색상: --accent-blue(정보), purple(처리), 빨강(위협)
5. 애니메이션: fade/scale/float (과하지 않게)
6. 구조: 정상 기능 → 해커 악용 교차 (2슬라이드 1쌍)
7. 해상도: 1280×720 고정 (반응형은 CSS scale로)
```

### 시나리오 게임 작성 기준
```
1. 장르: RPG / 수사 / 시뮬레이션 (몰입감 최우선)
2. 캐릭터: 팀장(멘토) + 에이전트(사용자) 최소 2명
3. 대화: speaker + text 구조, {AGENT} 치환
4. 씬: 3-5개 Sector (주제별 물리적 공간 분리)
5. 인터랙션: 단서 수집(클릭) + 퍼즐(triggerPuzzle)
6. 힌트: 각 씬에 hint 필드 (막히지 않도록)
7. 디자인: 고급스러운 테마 (로즈골드, 네온, 다크)
```
