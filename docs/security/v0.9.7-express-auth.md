# v0.9.7 — Express 서버 교체: edu HTML 서버 측 JWT 인증

> **날짜**: 2026-03-09
> **심각도**: 🔴 Critical
> **상태**: ✅ 해결

## 문제

프로덕션 서버가 `serve -s` (정적 파일 서버)로 실행되어 **서버 측 인증이 전혀 없었음**.

### 영향 범위
- edu HTML 200개 파일이 curl/Burp Suite로 인증 없이 완전 열람 가능
- 교육 콘텐츠 (MITRE ATT&CK 기법 해설, 보안 실습 자료) 무단 접근

### 재현 방법 (수정 전)
```bash
curl http://서버IP:4173/edu/t1583-001-domains.html
# → 200 OK + 30KB 전체 HTML 반환 (인증 없이)
```

### 기존 방어 현황
- 클라이언트 측 JS 인증만 존재 (sessionStorage 체크)
- JS를 실행하지 않는 도구 (curl, Burp, wget)에서는 우회 가능

## 원인

`serve -s`는 순수 정적 파일 서버로 미들웨어/인증 기능이 없음.
`window.sessionStorage`는 HTTP 헤더/쿠키로 전달되지 않아 서버에서 읽을 수 없음.

## 해결

### 아키텍처 변경

```
[변경 전]
pm2 → serve-prod.sh → serve -s dist/ (인증 없음)

[변경 후]
pm2 → serve-prod.sh → node server.js (Express + JWT 미들웨어)
```

### 인증 흐름

```
1. 로그인 시:
   Login.jsx → signInWithPassword() 성공
   → document.cookie = 'gotroot_auth_token=<access_token>'  (즉시)
   → AuthContext.jsx onAuthStateChange → 쿠키 동기화           (비동기)

2. edu HTML 접근 시:
   브라우저 → GET /edu/t1583.html (쿠키 자동 전송)
   → server.js 미들웨어: 쿠키에서 토큰 추출
   → Supabase API: GET /auth/v1/user (Bearer 토큰)
   → 200 OK → 파일 서빙
   → 401 → 302 /login 리다이렉트

3. 토큰 갱신 시:
   AuthContext.jsx onAuthStateChange(TOKEN_REFRESHED)
   → 쿠키 자동 업데이트

4. 로그아웃 시:
   AuthContext.jsx logout()
   → clearAuthCookie() (max-age=0)
   → supabase.auth.signOut()
```

### 성능 최적화
- **토큰 캐시**: 5분 TTL, 최대 1000개 (Supabase API 호출 최소화)
- **gzip 압축**: `compression` 미들웨어
- **정적 에셋 캐시**: 1일 (HTML 제외)

## NestJS 마이그레이션 호환성

이번 Express 구현은 NestJS 전환 시 100% 호환:

## 보안 헤더 강화 (2026-03-10 추가)

### 적용 헤더 목록

| 헤더 | 값 | 적용 대상 |
|------|-----|-----------|
| `X-Content-Type-Options` | `nosniff` | 전체 |
| `X-Frame-Options` | `DENY` | 전체 |
| `X-XSS-Protection` | `1; mode=block` | 전체 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 전체 |
| `Content-Security-Policy` | (아래 상세) | **SPA만** (edu 제외) |
| `Permissions-Policy` | 9개 API 차단 | 전체 |
| `Cross-Origin-Opener-Policy` | `same-origin` | 전체 |
| `Cross-Origin-Resource-Policy` | `same-origin` / `cross-origin` | SPA / edu 분리 |

### CSP 경로 분리 (핵심 설계)

```
[SPA 경로] /, /login, /mypage, /admin 등
  → 서버 CSP 헤더 적용 (index.html meta CSP와 이중 방어)
  → CORP: same-origin

[edu 경로] /edu/*.html, /edu/*.js, /edu/*.css
  → 서버 CSP 헤더 미적용 (자체 meta CSP 사용)
  → CORP: cross-origin
```

**분리 이유**:
- edu HTML은 `cdn.tailwindcss.com`, `fonts.googleapis.com` 등 외부 CDN 의존
- edu HTML에는 자체 `<meta http-equiv="Content-Security-Policy">` 태그 존재
- HTTP 헤더 CSP + meta CSP 동시 존재 시 **교차 적용**(둘 다 충족해야 함)
- 서버 CSP에 `cdn.tailwindcss.com` 미포함 → Tailwind 차단 → 디자인 깨짐 발생

### HSTS 비활성화 사유

```javascript
// res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
```

- **현재 구성**: HTTP 직접 서빙 (리버스 프록시 없음)
- **문제**: HSTS 헤더 → 브라우저가 HTTPS 강제 시도 → 연결 불가
- **위험**: 브라우저가 max-age 기간 동안 HSTS 캐시 → 헤더 제거해도 접속 불가 지속
- **해결**: Safari 캐시 초기화 필요 (`설정 → 개인정보 → 웹사이트 데이터 → localhost 삭제`)
- **활성화 조건**: Nginx/Cloudflare 리버스 프록시 도입 후 + HTTPS 인증서 설정 완료 시

### `upgrade-insecure-requests` CSP 비활성화 사유

- HSTS와 동일한 이유 — HTTP 서버에서 활성화 시 브라우저가 HTTPS로 자동 업그레이드 시도
- HTTPS 리버스 프록시 도입 후 활성화 예정

### Permissions-Policy 차단 API (9개)

```
camera, microphone, geolocation, payment, usb,

교육 플랫폼에서 불필요한 브라우저 API를 명시적으로 차단하여 공급망 공격 위험 감소.

### SPA 라우트 404 처리 — MITRE 기법 ID 대응

```
/edu/T1583.001 → extname() = '.001' → MITRE 기법 ID (파일 아님!)

- `STATIC_FILE_EXTS` 화이트리스트(30개 확장자)로 실제 정적 파일만 404 반환

## 교훈

- 정적 파일 서버는 인증 기능이 없음 — 민감한 콘텐츠는 반드시 미들웨어 보호
- sessionStorage는 서버에서 읽을 수 없음 — 서버 인증에는 쿠키 사용
- Express 5에서 `app.get('*')` → `app.use()` 또는 `app.get('{*path}')` 구문 변경 주의
- **HSTS는 HTTP 서버에서 절대 활성화하지 말 것** — 브라우저 캐시로 복구 어려움
- **보안 헤더 추가 전 경로별 리소스 의존성 조사 필수** — edu HTML vs SPA의 CDN 차이
- **CSP는 경로별로 분리 가능** — 서버 미들웨어에서 `req.path` 조건 분기
