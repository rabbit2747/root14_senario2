# v0.9.7 — ?preview=1 인증 우회 코드 제거

> **날짜**: 2026-03-09
> **심각도**: 🟡 Medium
> **상태**: ✅ 해결

## 문제

edu HTML 파일(200개)의 인증 스크립트에 `?preview=1` 파라미터가 있으면 **인증을 완전히 건너뛰는** 코드가 존재했음.

### 영향 범위
- 42개 edu HTML 파일에 해당 코드 존재
- URL에 `?preview=1`만 추가하면 비로그인 사용자도 교육 콘텐츠 열람 가능

### 재현 방법
```bash
curl http://example.com/edu/t1583-001-domains.html?preview=1
# → 200 OK + 전체 교육 콘텐츠 반환 (인증 없이)
```

## 원인

관리자 페이지(EduHtmlEditor)의 iframe 프리뷰 기능을 위해 추가된 코드:
```javascript
// 문제의 코드 (제거됨)
if (new URLSearchParams(window.location.search).get('preview') === '1') return;
```

프리뷰 용도였으나, 외부에서도 동일 파라미터로 인증 우회 가능.

## 해결

### 변경 사항
1. **42개 edu HTML**: `?preview=1` 인증 스킵 라인 일괄 제거
2. **t1078-002 추가 정리**: 주석 형태의 `// preview=1` 참조 제거

### 실행 명령
```bash
# 일괄 제거
sed -i '' "/if (new URLSearchParams(window.location.search).get('preview') === '1') return;/d" public/edu/*.html

# 주석 제거
sed -i '' '/\/\/ preview=1/d' public/edu/t1078-002-domain-accounts.html
```

### 제거 후 인증 코드 (유지됨)
```html
<script>
    (function() {
        try {
            var key = 'sb-bnwbybawqrnhznirivfg-auth-token';
            var session = sessionStorage.getItem(key);
            if (!session || !JSON.parse(session)) {
                var redirect = encodeURIComponent(window.location.href);
                window.location.replace('/login?redirect=' + redirect);
            }
        } catch(e) { window.location.replace('/login'); }
    })();
</script>
```

## 검증

```bash
# ?preview=1 우회 불가 확인
curl -s http://127.0.0.1:4173/edu/t1583-001-domains.html?preview=1
# → 302 Redirect to /login (서버 측 Express 인증에 의해 차단)

# 잔여 코드 없음 확인
grep -r "preview.*===.*'1'" public/edu/ | wc -l
# → 0
```

## 교훈

- 개발 편의용 인증 우회 코드는 프로덕션에 절대 남기지 말 것
- iframe 프리뷰는 인증된 API 엔드포인트로 구현할 것
