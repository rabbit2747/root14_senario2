컴퓨터 메모리 속에 비밀번호가 남아있다면?

Windows 시스템에서 사용자가 로그인하면, 운영체제는 인증 정보를 LSASS(Local Security Authority Subsystem Service)라는 프로세스 메모리에 보관합니다. 공격자는 이 메모리를 읽어 비밀번호, 해시, Kerberos 티켓 등을 탈취할 수 있습니다. 마치 호텔 프런트에 보관된 객실 마스터키를 훔치는 것과 같습니다.

#1. LSASS란 무엇인가?

🏨🔑

호텔 프런트의 마스터키 금고

호텔에 투숙하면 프런트에서 객실 키를 발급받습니다. 하지만 프런트 직원은 모든 객실을 열 수 있는 마스터키를 금고에 보관하고 있죠. LSASS는 이 마스터키 금고와 같습니다. 사용자가 로그인하면 Windows는 인증 정보(비밀번호 해시, Kerberos 티켓 등)를 LSASS 프로세스 메모리에 보관합니다. 이는 SSO(Single Sign-On)나 네트워크 인증에 필요하기 때문입니다.

⚙️

LSASS 프로세스의 역할

LSASS(Local Security Authority Subsystem Service)는 Windows 보안의 핵심 프로세스입니다. 주요 역할: ① 사용자 로그인 인증 처리, ② 보안 토큰 생성 및 관리, ③ 보안 정책 적용, ④ 보안 감사 로그 기록. lsass.exe는 항상 실행 중이며, 이 프로세스가 중단되면 시스템이 즉시 재시작됩니다.

LSASS에 저장되는 자격증명 유형

유형 설명 위험도
NTLM 해시 비밀번호의 해시값 (Pass-the-Hash 공격 가능) 🔴 높음
Kerberos 티켓 도메인 인증용 티켓 (Golden Ticket 공격 가능) 🔴 높음
평문 비밀번호 WDigest 활성 시 평문 저장 (구버전) 🔴 매우 높음
PIN/생체인증 키 Windows Hello 인증 키 🟡 중간

#2. 공격 원리: 메모리에서 비밀번호 꺼내기

👀🔓

금고를 열지 않고 엿보는 법

마스터키 금고를 직접 열지 못하더라도, 금고의 틈새로 들여다보거나 금고의 사본을 만들 수 있다면? 공격자는 LSASS 프로세스의 메모리를 '읽는' 방식으로 자격증명을 탈취합니다. 이는 금고 자체를 파괴하지 않으면서도 그 안의 내용물을 복사하는 것과 같습니다.

🎯

공격의 3단계

LSASS 메모리 덤프 공격은 3단계로 진행됩니다: ① 권한 획득 — 관리자 권한이 필요합니다 (SeDebugPrivilege). ② 메모리 접근 — LSASS 프로세스의 메모리를 읽거나 덤프 파일로 저장합니다. ③ 자격증명 추출 — 덤프된 데이터에서 비밀번호 해시, 티켓 등을 파싱합니다.

LSASS 덤프 공격 흐름

  [공격자]                    [대상 시스템]
     │                           │
     ├── ① 관리자 권한 획득 ──→ │
     │                           │
     ├── ② LSASS PID 확인 ───→  │  lsass.exe (PID: 672)
     │                           │
     ├── ③ 메모리 덤프 ────→    │  MiniDumpWriteDump()
     │                           │      │
     │                           │      ▼
     │                     [lsass.dmp 파일 생성]
     │                           │
     ├── ④ 파일 전송 ←──────    │
     │                           │
     ▼                           │
 [오프라인 분석]                  │
  Mimikatz로                     │
  자격증명 추출                  │

#3. 주요 공격 도구 개요

🛠️

대표적인 LSASS 덤프 도구들

공격자들이 LSASS 메모리를 덤프하는 데 사용하는 주요 도구: ① Mimikatz — 가장 유명한 자격증명 탈취 도구. sekurlsa::logonpasswords 명령으로 직접 추출. ② ProcDump — Microsoft의 공식 시스템 진단 도구. 합법적 도구이므로 탐지가 어려움. ③ comsvcs.dll — Windows 내장 DLL. rundll32.exe로 호출하여 미니덤프 생성. ④ Task Manager — Windows 작업 관리자에서도 프로세스 덤프 가능.

도구별 특성 비교

도구 유형 탐지 난이도 사용 빈도
Mimikatz 전용 공격 도구 🟢 쉬움 ★★★★★
ProcDump 합법적 MS 도구 🟡 중간 ★★★★☆
comsvcs.dll Windows 내장 🔴 어려움 ★★★☆☆
Task Manager Windows 기본 🔴 매우 어려움 ★★☆☆☆
Direct syscall 커스텀 코드 🔴 매우 어려움 ★★★☆☆

⚠️ 교육 목적 안내

이 강의에서 소개하는 도구와 기법은 보안 전문가가 방어 전략을 수립하기 위해 '공격 원리를 이해하는 것'이 목적입니다. 허가 없이 타인의 시스템에 이러한 기법을 사용하면 법적 처벌을 받을 수 있습니다.

#4. 실제 사이버 공격 사례

🐻

APT29 (Cozy Bear) — SolarWinds 공격

러시아 정부와 연계된 APT29는 2020년 SolarWinds 공급망 공격에서 LSASS 메모리 덤프를 핵심 기법으로 사용했습니다. 초기 침투 후 Mimikatz 변형을 이용해 도메인 관리자 자격증명을 탈취하고, 이를 Golden Ticket 공격으로 연결하여 Microsoft 365 환경까지 침투했습니다.

💰

Lazarus Group — 금융기관 공격

북한 정찰총국과 연계된 Lazarus Group은 SWIFT 은행 시스템 공격에서 자격증명 탈취를 적극 활용했습니다. 대상 시스템의 LSASS 메모리에서 추출한 자격증명으로 내부 네트워크를 횡단이동(Lateral Movement)하여 핵심 금융 시스템에 접근했습니다.

🇰🇷

한국 사례: 국내 금융기관 침해

KISA 침해사고 분석 보고서에 따르면, 국내 금융기관 대상 APT 공격에서도 LSASS 메모리 덤프가 빈번하게 사용되었습니다. 특히 comsvcs.dll을 이용한 Living-off-the-Land(LotL) 기법이 다수 탐지되었으며, 이는 기존 안티바이러스를 우회하기 위한 전략이었습니다.

#5. 기본 방어 전략

🛡️

핵심 방어 메커니즘

LSASS 메모리 덤프를 방어하는 핵심 기술: ① Credential Guard — 가상화 기반으로 LSASS를 격리. ② PPL (Protected Process Light) — LSASS를 보호 프로세스로 설정하여 일반 프로세스의 메모리 접근 차단. ③ WDigest 비활성화 — 레지스트리 설정으로 평문 비밀번호 저장 방지.

방어 수단 비교

방어 수단 효과 적용 조건 우회 가능성
Credential Guard NTLM 해시 보호 VBS 지원 하드웨어 커널 취약점
PPL 메모리 접근 차단 Win 8.1+ 드라이버 취약점
WDigest 비활성화 평문 저장 방지 레지스트리 설정 없음
LSA RunAsPPL LSASS 보호 Win 10+ 커널 취약점
LSASS UEFI Lock 부팅 시 잠금 Win 11+ 하드웨어 공격
🔍

탐지 관점: 어떤 로그를 봐야 할까?

LSASS 메모리 접근을 탐지하는 핵심 로그: ① Sysmon Event ID 10 — 프로세스 접근 이벤트 (TargetImage에 lsass.exe 필터). ② Windows Security Event 4656/4663 — 객체 핸들 요청/접근 감사. ③ Windows Defender Alert — LSASS 접근 이상 행위 탐지. 이런 로그를 SIEM에서 모니터링하면 초기 단계에서 공격을 탐지할 수 있습니다.

#Q. 종합 퀴즈

Q1. LSASS 프로세스가 자격증명을 메모리에 보관하는 주된 이유는?

💡 LSASS는 SSO(Single Sign-On)와 네트워크 리소스 접근 시 반복적인 인증을 방지하기 위해 자격증명을 메모리에 캐시합니다. 이 설계가 편의성과 보안의 트레이드오프입니다.

Q2. 다음 중 합법적인 Microsoft 도구를 악용한 LSASS 덤프 방법은?

💡 ProcDump는 Microsoft에서 공식 배포하는 시스템 진단 도구입니다. -ma 옵션으로 lsass.exe의 전체 메모리를 덤프할 수 있어, Living-off-the-Land 기법의 대표적 사례입니다.

Q3. Credential Guard의 핵심 보호 원리는?

💡 Credential Guard는 하드웨어 가상화(VBS)를 이용하여 LSASS 프로세스를 격리된 컨테이너에서 실행합니다. 이로 인해 관리자 권한이 있더라도 메모리에서 자격증명을 읽을 수 없습니다.

Q4. LSASS 메모리 접근을 탐지하는 가장 효과적인 Sysmon 이벤트 ID는?

💡 Sysmon Event ID 10은 프로세스 간 메모리 접근을 기록합니다. TargetImage 필드에 lsass.exe를 필터링하면 LSASS에 대한 비정상적 접근 시도를 효과적으로 탐지할 수 있습니다.

Q5. SolarWinds 공급망 공격에서 LSASS 덤프를 활용한 APT 그룹은?

💡 APT29(Cozy Bear)는 러시아 정부와 연계된 그룹으로, 2020년 SolarWinds 공급망 공격에서 LSASS 메모리 덤프를 통해 도메인 관리자 자격증명을 탈취하고 Golden Ticket 공격으로 Microsoft 365까지 침투했습니다.
