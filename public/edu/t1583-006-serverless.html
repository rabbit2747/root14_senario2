#1. 서버리스란?

⚡ ➜ ☁️ ➜ 🔄 ➜ 💨

"서버 없이 코드를 실행한다"

서버리스(Serverless)는 클라우드 제공업체가 서버를 관리하고, 개발자는 코드만 업로드하면 되는 컴퓨팅 모델입니다. AWS Lambda, Azure Functions, Google Cloud Functions, Cloudflare Workers가 대표적입니다. 사용한 만큼만 과금되고, 실행 후 자동으로 리소스가 해제됩니다.

🎭 ➜ ⚡ ➜ 💨 ➜ ❌

"일회용 공격 인프라"

공격자는 서버리스를 일회용 공격 인프라로 활용합니다. 도난 신용카드나 무료 계정으로 함수를 배포하고, 공격 후 삭제하면 흔적이 거의 남지 않습니다. IP는 클라우드 제공업체의 것이므로 추적이 극히 어렵습니다.

#2. 공격자의 서버리스 활용

C2 릴레이

Lambda 함수가 C2 서버와 감염 호스트 사이의 릴레이 역할을 합니다. amazonaws.com 도메인이므로 방화벽에서 허용됩니다.

POST xyz.lambda.amazonaws.com
→ relay to C2 backend

피싱 프록시

Cloudflare Workers로 피싱 페이지를 호스팅합니다. workers.dev 도메인은 SSL이 자동 적용되어 신뢰성이 높아 보입니다.

https://login-portal.workers.dev
→ credential harvesting

크립토마이너

도난 계정으로 수백 개의 Lambda 함수를 동시에 실행하여 암호화폐를 채굴합니다. 비용은 피해자의 클라우드 계정에 청구됩니다.

× 500 concurrent executions
→ $12,000/day mining

데이터 유출 터널

Azure Functions를 통해 탈취한 데이터를 외부로 전송합니다. azurewebsites.net 트래픽은 정상 클라우드 트래픽으로 보입니다.

POST exfil.azurewebsites.net
→ data chunks uploaded

포렌식 관점에서의 어려움

  • ● 함수 삭제 시 실행 환경이 완전히 소멸 — 디스크 포렌식 불가
  • ● IP가 클라우드 제공업체 소유 — 공격자 추적 어려움
  • ● 무료 티어로 익명 사용 가능 — 결제 추적 불가
  • ● 로그 보존 기간이 짧아 증거 수집 시간 제한

#3. 탐지와 방어 전략

네트워크 탐지

  • - workers.dev, lambda-url.* 등 서버리스 도메인 모니터링
  • - 비정상적 패턴의 클라우드 API 호출 탐지
  • - 서버리스 엔드포인트로의 대량 데이터 전송 감시

클라우드 보안

  • - 조직 내 서버리스 함수 인벤토리 관리
  • - IAM 권한 최소화 및 이상 활동 알림
  • - CloudTrail/CloudWatch 로그 장기 보존 설정
