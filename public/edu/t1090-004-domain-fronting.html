Domain Fronting

CDN 뒤에 숨은 C2 — 합법적 도메인으로 위장한 비밀 통신

#1. Domain Fronting이란?

🌐 ➜ 🏢 ➜ 🎭 ➜ 💀

"합법적 CDN 뒤에 C2 서버를 숨기는 기술"

Domain Fronting은 HTTPS SNI(Server Name Indication)와 HTTP Host 헤더의 차이를 악용합니다. 네트워크 장비에는 합법적 도메인(예: google.com)으로 접속하는 것처럼 보이지만, 실제로는 같은 CDN 뒤에 있는 C2 서버로 트래픽이 라우팅됩니다.

왜 탐지가 어려운가?

방화벽은 TLS 핸드셰이크의 SNI 필드만 봅니다. SNI에 "google.com"이 적혀 있으면 정상 트래픽으로 판단합니다. 그러나 TLS 암호화 터널 내부의 HTTP Host 헤더에는 실제 C2 도메인이 들어있습니다. CDN이 이 Host 헤더를 기반으로 실제 목적지로 라우팅합니다.

#2. CDN 악용 메커니즘

SNI vs Host 헤더

TLS ClientHello의 SNI 필드는 암호화 전에 전송되어 방화벽이 읽을 수 있습니다. 반면 HTTP Host 헤더는 TLS 터널 내부에 있어 복호화 없이는 볼 수 없습니다. 해커는 SNI에 합법적 도메인을, Host에 C2 도메인을 넣습니다.

CDN 라우팅 원리

CDN은 Host 헤더를 기반으로 백엔드를 결정합니다. 같은 CDN을 사용하는 도메인이라면 SNI와 Host가 달라도 CDN이 올바른 백엔드로 라우팅합니다. 해커의 C2 서버가 같은 CDN에 호스팅되어 있으면 이 기법이 작동합니다.

실전 사례: APT29 Domain Fronting

러시아 APT29(Cozy Bear)는 Meek 플러그인과 CloudFront를 이용하여 Domain Fronting을 수행했습니다. 외부에서는 합법적인 CDN 트래픽으로 보이지만, 실제로는 Tor 네트워크를 통해 C2와 통신했습니다.

# Domain Fronting 패킷 분석
TLS ClientHello SNI: cdn.google.com
HTTP Host (encrypted): c2-evil.cloudfront.net
CDN Route: c2-evil.cloudfront.net → 185.xx.xx.xx
# 방화벽은 google.com만 보이지만 실제로는 C2로 통신
