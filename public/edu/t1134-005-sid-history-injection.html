T1134.005: SID-History Injection

Privilege Escalation

SID-History Injection

일반 직원 ID에 관리자 권한을 몰래 추가하는 Active Directory 공격

#1. SID-History란?

"이전 회사 사원증" 비유

회사가 합병되면 직원들의 사원증 번호가 바뀝니다. 하지만 이전 회사의 시스템에도 접근해야 하므로, 새 사원증에 "이전 사원번호"를 기록해 둡니다. 이것이 SID-History입니다. Active Directory에서 도메인 마이그레이션 시 이전 도메인의 SID를 보존하는 기능입니다.

SID(Security Identifier) 구조

# SID 구조 예시
S-1-5-21-3623811015-3361044348-30300820-500
도메인 식별자 ──────────────────── RID(500=Administrator)
1RID 500 = Domain Administrator (built-in)
2RID 512 = Domain Admins 그룹
3RID 519 = Enterprise Admins 그룹

#2. SID-History 주입 공격

Mimikatz를 이용한 SID-History 주입

도메인 관리자 권한을 획득한 공격자가 일반 사용자 계정에 Enterprise Admin의 SID(RID 519)를 SID-History에 주입합니다. 이후 이 계정으로 로그인하면 Enterprise Admin과 동일한 권한을 갖게 됩니다. 일반 계정처럼 보이지만 실제로는 최고 관리자입니다.

# Mimikatz SID-History 주입 예시
mimikatz # privilege::debug
mimikatz # sid::patch
mimikatz # sid::add /sam:normaluser /new:S-1-5-21-...-519
[+] SID-History added successfully

방어 방법

  • SID Filtering: 포레스트 트러스트에서 SID-History를 필터링 (기본 활성화)
  • Event ID 4765/4766: SID-History 추가/제거 이벤트 모니터링
  • AD 정기 감사: Get-ADUser -Filter * -Properties SIDHistory로 비정상 SID-History 탐지
