01

보안 환경에서 피싱 실패 체감

🎯 학습 목표

보안 솔루션이 갖춰진 환경에서 스피어피싱 공격이 어떻게 차단되는지 전체 흐름을 이해합니다.

왜 중급부터 "방어"를 먼저 배울까?

초급 과정에서 공격자의 도구와 기법을 배웠습니다. 이제 방어자(Blue Team) 시점에서 동일한 공격이 어떻게 탐지되고 차단되는지 배울 차례입니다. 실무 보안 운영에서는 공격 기법을 아는 것만큼 탐지 규칙을 작성하고 검증하는 능력이 중요합니다.

보안 계층 방어 (Defense in Depth)

스피어피싱 첨부파일 공격은 단일 보안 솔루션이 아닌 다층 방어(Layered Defense)에 의해 차단됩니다. 각 계층이 하나의 체크포인트 역할을 합니다.

공격자가 피싱 메일 발송
      │
      ▼
┌─────────────────────────────────────┐
│ Layer 1: 이메일 게이트웨이 (SEG)     │ ← SPF/DKIM/DMARC 검증
│   → 발신자 위조 탐지, 첨부파일 샌드박스 │    악성 첨부 격리
└─────────────────────────────────────┘
      │ (통과 시)
      ▼
┌─────────────────────────────────────┐
│ Layer 2: 엔드포인트 (EDR/ASR)        │ ← 매크로 실행 차단
│   → ASR Rule, AMSI 스캔, 행위 분석   │    PowerShell 모니터링
└─────────────────────────────────────┘
      │ (통과 시)
      ▼
┌─────────────────────────────────────┐
│ Layer 3: 네트워크 (NDR/Proxy)        │ ← C2 통신 차단
│   → DNS 싱크홀, SSL 복호화, IDS/IPS  │    비정상 트래픽 탐지
└─────────────────────────────────────┘
      │ (통과 시)
      ▼
┌─────────────────────────────────────┐
│ Layer 4: SIEM/SOC 모니터링           │ ← 로그 상관분석
│   → Sysmon + Sigma 규칙 → 알림 발생  │    인시던트 대응 개시
└─────────────────────────────────────┘

이 과정에서 배우는 도구들

Sysmon

프로세스/네트워크 이벤트 로깅

YARA

파일 패턴 매칭 규칙

Sigma

로그 기반 탐지 규칙

ASR

Attack Surface Reduction

💡 핵심 포인트

초급에서 배운 공격 기법(GoPhish, msfvenom, VBA 매크로)이 실제 보안 환경에서 어느 계층에서 탐지·차단되는지 매핑하면서 학습하면 효과적입니다.

02

이메일 게이트웨이 차단 분석

🎯 학습 목표

SPF, DKIM, DMARC 인증이 스피어피싱을 차단하는 원리와 이메일 보안 게이트웨이(SEG)의 동작 방식을 분석합니다.

SPF (Sender Policy Framework)

SPF는 DNS TXT 레코드에 허용된 발신 서버 IP를 등록하여, 수신 서버가 발신자의 정당성을 검증하는 프로토콜입니다. 공격자가 위조한 발신 주소는 SPF 검증에서 실패합니다.

# DNS TXT 레코드 조회
$ dig TXT example.com +short
"v=spf1 ip4:203.0.113.0/24 include:_spf.google.com -all"

# SPF 검증 결과 (이메일 헤더에서 확인)
Authentication-Results: mx.google.com;
    spf=fail (google.com: domain of ceo@example.com
    does not designate 185.234.72.11 as permitted sender)
    smtp.mailfrom=ceo@example.com

DKIM (DomainKeys Identified Mail)

DKIM은 발신 서버가 이메일에 암호화 서명을 추가하여, 수신 서버가 이메일 본문이 전송 중 변조되지 않았음을 검증합니다. 공격자는 합법적 도메인의 개인키를 가지고 있지 않으므로 DKIM 서명을 위조할 수 없습니다.

DMARC (Domain-based Message Authentication)

DMARC는 SPF와 DKIM 결과를 결합하여 최종 처리 정책을 결정합니다. p=reject로 설정하면 인증 실패 메일이 완전히 거부됩니다.

# DMARC 정책 레코드
$ dig TXT _dmarc.example.com +short
"v=DMARC1; p=reject; rua=mailto:dmarc@example.com; pct=100"

# 정책 옵션 비교
p=none    → 모니터링만 (차단 안 함, 보고서만 수집)
p=quarantine → 스팸 폴더로 격리
p=reject  → 완전 거부 (가장 강력)

SEG의 첨부파일 분석

Secure Email Gateway는 인증 외에도 첨부파일을 샌드박스에서 실행하여 악성 행위를 탐지합니다. 매크로 포함 문서(.docm), 실행 파일(.exe), 스크립트(.vbs, .js) 등이 분석 대상입니다.

SEG 첨부파일 처리 흐름:

① 확장자/MIME 타입 검사 → ② 정적 AV 스캔 (시그니처 매칭) → ③ 샌드박스 동적 분석 (2~3분) → ④ 판정: Clean / Suspicious / Malicious

⚠️ 실무 참고

SPF/DKIM/DMARC는 발신자 위조(Spoofing)를 차단하지만, 공격자가 합법적 메일 서비스(Gmail 등)로 발송하면 통과될 수 있습니다. 따라서 Layer 2 이상의 방어가 반드시 필요합니다.

03

ASR Rule 매크로 차단 분석

🎯 학습 목표

Windows Defender의 ASR(Attack Surface Reduction) 규칙이 Office 매크로 기반 공격을 차단하는 메커니즘을 분석합니다.

ASR이란?

ASR(Attack Surface Reduction)은 Microsoft Defender for Endpoint의 기능으로, 공격자가 자주 악용하는 행위 패턴을 사전에 차단합니다. 시그니처가 아닌 행위(behavior) 기반이므로 알려지지 않은 공격도 차단할 수 있습니다.

피싱 관련 핵심 ASR 규칙

규칙 이름 GUID 차단 대상
Office 앱의 자식 프로세스 생성 차단D4F940AB-401B-4EFC-AADC-AD5F3C50688AWord→cmd.exe, PowerShell
Office 앱의 실행 콘텐츠 생성 차단3B576869-A4EC-4529-8536-B80A7769E899.exe, .dll 파일 생성
Office 매크로의 Win32 API 호출 차단92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7BVBA → CreateProcess 등
난독화된 스크립트 실행 차단5BEB7EFE-FD9A-4556-801D-275E5FFC04CCAMSI 난독화 탐지

ASR 규칙 배포 (PowerShell / GPO)

# PowerShell: ASR 규칙 활성화 (Block 모드)
Set-MpPreference -AttackSurfaceReductionRules_Ids `
    D4F940AB-401B-4EFC-AADC-AD5F3C50688A `
    -AttackSurfaceReductionRules_Actions Enabled

# 현재 ASR 규칙 상태 확인
Get-MpPreference | Select-Object -ExpandProperty AttackSurfaceReductionRules_Ids

# ASR 이벤트 로그 확인
Get-WinEvent -LogName "Microsoft-Windows-Windows Defender/Operational" |
    Where-Object { $_.Id -eq 1121 -or $_.Id -eq 1122 } |
    Select-Object TimeCreated, Message -First 10

🔴 초급 과정 연결

초급 Ch.6에서 배운 Sub AutoOpen() → Shell("powershell...") 공격은 ASR 규칙 D4F940AB가 "Office 자식 프로세스 생성"을 차단하여 무력화됩니다.

04

Sysmon 이벤트 ID별 탐지 분석

🎯 학습 목표

Sysmon(System Monitor)의 핵심 이벤트 ID를 이해하고, 스피어피싱 공격 체인의 각 단계에서 어떤 이벤트가 생성되는지 분석합니다.

Sysmon이란?

Sysmon은 Microsoft의 Sysinternals 도구로, Windows 이벤트 로그에 상세한 프로세스/네트워크/파일 활동을 기록합니다. 기본 Windows 이벤트 로깅보다 훨씬 정밀한 정보를 제공하므로, SOC 분석에 필수적입니다.

피싱 공격 탐지용 핵심 이벤트 ID

ID 1

Process Create

프로세스 생성 기록. WINWORD.EXE → cmd.exe → powershell.exe 체인 탐지의 핵심

ID 3

Network Connection

네트워크 연결 기록. C2 서버로의 아웃바운드 연결 탐지

ID 7

Image Loaded

DLL 로드 기록. 악성 DLL 사이드로딩 탐지

ID 11

File Create

파일 생성 기록. %TEMP%에 드롭되는 페이로드 탐지

공격 체인과 Sysmon 이벤트 매핑

═══ 스피어피싱 공격 → Sysmon 이벤트 체인 ═══

[사용자가 첨부파일 열기]
  └→ Event ID 1  WINWORD.EXE 실행 (ParentImage: explorer.exe)

[매크로 실행 → cmd.exe 호출]
  └→ Event ID 1  cmd.exe 실행 (ParentImage: WINWORD.EXE) ⚠️ 핵심 탐지 포인트

[PowerShell 다운로더 실행]
  └→ Event ID 1  powershell.exe -enc base64... (ParentImage: cmd.exe)

[페이로드 다운로드]
  └→ Event ID 3  powershell.exe → 외부 IP:443 연결
  └→ Event ID 11 C:\Users\*\AppData\Local\Temp\payload.exe 파일 생성

[페이로드 실행 → C2 통신]
  └→ Event ID 1  payload.exe 실행 (ParentImage: powershell.exe)
  └→ Event ID 3  payload.exe → C2서버:8443 연결

Sysmon 설치 및 구성

# Sysmon 설치 (SwiftOnSecurity 구성 파일 사용)
sysmon64.exe -accepteula -i sysmonconfig-export.xml

# 이벤트 로그 조회 (PowerShell)
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" |
    Where-Object { $_.Id -eq 1 } |
    Where-Object { $_.Message -match "WINWORD.EXE" -and $_.Message -match "cmd.exe" } |
    Format-List TimeCreated, Message

💡 핵심 포인트

가장 중요한 탐지 포인트는 Event ID 1에서 WINWORD.EXE가 cmd.exe 또는 powershell.exe의 부모 프로세스인 경우입니다. 정상적인 Word 사용에서는 이런 프로세스 체인이 발생하지 않습니다.

05

YARA 규칙으로 피싱 탐지

🎯 학습 목표

YARA 규칙의 구조를 이해하고, 스피어피싱 첨부파일(매크로 문서)을 탐지하는 기본 규칙을 작성합니다.

YARA란?

YARA는 패턴 매칭 기반의 악성코드 분류 도구입니다. 파일 내 문자열, 바이트 패턴, 파일 크기, 구조적 특징을 조합하여 탐지 규칙을 작성합니다. SOC, 악성코드 분석가, 위협 인텔리전스 팀에서 광범위하게 사용됩니다.

YARA 규칙 기본 구조

// 스피어피싱 매크로 문서 탐지 규칙
rule Spearphish_Macro_Document {
    meta:
        description = "VBA 매크로가 포함된 의심 문서 탐지"
        author      = "ROOT14 SOC Team"
        severity    = "high"
        mitre_att   = "T1566.001"

    strings:
        // OLE2 문서 매직 바이트 (Word/Excel)
        $ole2_magic = { D0 CF 11 E0 A1 B1 1A E1 }

        // VBA 프로젝트 스트림 식별자
        $vba_project = "VBA" ascii wide
        $vba_dir     = "_VBA_PROJECT" ascii

        // 의심 VBA 키워드
        $auto_open   = "AutoOpen" ascii nocase
        $auto_close  = "Auto_Close" ascii nocase
        $shell_exec  = "Shell" ascii nocase
        $wscript     = "WScript.Shell" ascii nocase
        $powershell  = "powershell" ascii nocase

    condition:
        $ole2_magic at 0
        and $vba_project
        and any of ($auto_open, $auto_close)
        and any of ($shell_exec, $wscript, $powershell)
}

YARA 실행 및 결과 해석

# 단일 파일 스캔
$ yara spearphish_rule.yar suspicious_invoice.docm
Spearphish_Macro_Document suspicious_invoice.docm

# 디렉토리 전체 재귀 스캔
$ yara -r spearphish_rule.yar /quarantine/emails/

# 매칭 문자열 상세 출력
$ yara -s spearphish_rule.yar suspicious_invoice.docm
Spearphish_Macro_Document suspicious_invoice.docm
0x0:$ole2_magic: D0 CF 11 E0 A1 B1 1A E1
0x1a2b:$auto_open: AutoOpen
0x1c4f:$shell_exec: Shell
0x2031:$powershell: powershell

YARA 규칙 핵심 키워드

meta:

규칙 메타데이터 (설명, 작성자, 심각도)

strings:

탐지할 문자열/바이트 패턴 정의

condition:

strings 조합 논리 (and, or, any of)

{ hex bytes }

16진수 바이트 시퀀스 매칭

💡 실무 팁

YARA는 파일 자체를 분석합니다. 이메일 수신 시 첨부파일을 추출하여 YARA 스캔을 수행하고, Sysmon은 실행 행위를 로깅합니다. 두 도구는 상호 보완적입니다.

06

Sigma 규칙 기초

🎯 학습 목표

Sigma 규칙의 YAML 구조를 이해하고, 스피어피싱 공격의 프로세스 체인을 탐지하는 기본 Sigma 규칙을 분석합니다.

Sigma란?

Sigma는 SIEM 독립적인 탐지 규칙 언어입니다. YAML 형식으로 작성하며, 변환기(Sigmac/pySigma)를 통해 Splunk, Elastic, Sentinel 등 어떤 SIEM 플랫폼의 쿼리로도 변환할 수 있습니다. YARA가 "파일"을 탐지한다면, Sigma는 "로그"를 탐지합니다.

Sigma 규칙 구조

# Sigma 규칙: Office 앱에서 의심 자식 프로세스 생성 탐지
title: Suspicious Office Child Process - Spearphishing Indicator
id: e42867ac-1a2b-3c4d-5e6f-789012345678
status: experimental
description: >
    Office 애플리케이션이 cmd.exe, powershell.exe, mshta.exe 등
    의심스러운 자식 프로세스를 생성하는 패턴을 탐지합니다.
    스피어피싱 첨부파일의 매크로 실행을 나타낼 수 있습니다.

references:
    - https://attack.mitre.org/techniques/T1566/001/

author: ROOT14 SOC Team
date: 2026/03/18
tags:
    - attack.initial_access
    - attack.t1566.001
    - attack.execution
    - attack.t1204.002

logsource:
    category: process_creation
    product: windows

detection:
    selection_parent:
        ParentImage|endswith:
            - '\WINWORD.EXE'
            - '\EXCEL.EXE'
            - '\POWERPNT.EXE'
            - '\OUTLOOK.EXE'

    selection_child:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\mshta.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\certutil.exe'
            - '\regsvr32.exe'

    condition: selection_parent and selection_child

falsepositives:
    - 정상적인 Office 매크로 자동화 (IT부서 검증 필요)
    - COM Add-in이 프로세스를 생성하는 경우

level: high

YARA vs Sigma 비교

항목 YARA Sigma
대상파일 (바이너리, 문서)로그 (이벤트, 시스로그)
형식자체 문법YAML
타이밍수신/저장 시점 (정적)실행 시점 (동적)
변환직접 실행pySigma → Splunk/Elastic/Sentinel

💡 핵심 포인트

Sigma는 "어떤 로그 패턴이 의심스러운가"를 정의합니다. 위 규칙에서 ParentImage: WINWORD.EXE + Image: cmd.exe 조합이 Ch.4에서 배운 Sysmon Event ID 1 로그와 정확히 매칭됩니다.

07

이메일 헤더 포렌식 실습

🎯 학습 목표

스피어피싱 이메일의 전체 헤더를 분석하여 발신자 위조, 경유 서버, 인증 실패 등 이상 징후를 식별합니다.

이메일 헤더 구조

이메일 헤더는 아래에서 위로 읽어야 합니다. 각 MTA(Mail Transfer Agent)가 Received 헤더를 위에 추가하므로, 가장 아래의 Received가 최초 발송 서버입니다.

═══ 피싱 이메일 헤더 예제 (이상 징후 포함) ═══

Return-Path: <bounce@attacker-mail.xyz>               ← [1] 실제 반송 주소 ≠ From
Received: from gateway.company.com (mx1.company.com [10.0.0.5])
    by internal-mx.company.com; Tue, 18 Mar 2026 09:15:33 +0900
Received: from mail-out.attacker-mail.xyz (unknown [185.234.72.11])
    by gateway.company.com; Tue, 18 Mar 2026 09:15:31 +0900 ← [2] 발신 IP
Authentication-Results: gateway.company.com;
    spf=fail (sender IP not authorized)              ← [3] SPF 실패

[1]

Return-Path와 From 불일치: 반송 주소가 attacker-mail.xyz인데 From은 company.com

[2]

[3]

[4]

[6]

[7]

08

공격자 → 방어자 관점 전환

🎯 학습 목표

초급에서 배운 공격 기법을 방어자 시점으로 재분석하고, 각 공격 단계별 탐지·차단 전략을 설계합니다.

공격 체인 vs 방어 체인 매핑

초급에서 배운 공격 7단계를 방어자 관점에서 1:1 매핑합니다. 공격의 각 단계마다 탐지(Detect), 차단(Block), 대응(Respond) 기회가 존재합니다.

공격 단계 (초급) 공격자 도구 방어 대응 (중급) 탐지 도구
① 정찰·목표 선정OSINT임직원 노출 정보 관리-
② 피싱 메일 발송GoPhish, SETSPF/DKIM/DMARC + SEG이메일 게이트웨이
③ 사용자 파일 오픈사회공학보안 인식 교육피싱 신고 버튼
④ 매크로 실행VBA AutoOpenASR Rule + 매크로 차단Defender 이벤트
⑤ PowerShell 다운로더msfvenomAMSI + Constrained LanguageSysmon ID 1
⑥ 페이로드 실행MeterpreterEDR 행위 분석Sysmon ID 1,7,11
⑦ C2 통신Reverse ShellDNS 싱크홀 + NDRSysmon ID 3, NDR

MITRE ATT&CK Detection Coverage

Detection Coverage란 ATT&CK 매트릭스의 기법 중 몇 개에 대해 탐지 규칙이 존재하는지를 나타내는 지표입니다. SOC 성숙도를 측정하는 핵심 KPI로 사용됩니다.

T1566.001에 대한 탐지 커버리지 예시:

이메일 게이트웨이: SPF/DKIM/DMARC 검증 ✅
ASR: Office 자식 프로세스 차단 ✅
Sysmon + Sigma: 프로세스 체인 탐지 ✅
YARA: 매크로 문서 정적 분석 ✅
NDR: C2 트래픽 탐지 ⚠️ (암호화 채널 시 제한적)

💡 핵심 포인트

공격자가 하나의 기법을 사용하더라도, 방어자는 여러 계층에서 탐지 기회를 확보해야 합니다. 어느 한 계층이 실패해도 다른 계층이 잡아낼 수 있도록 설계하는 것이 Defense in Depth의 핵심입니다.

09

GPO/ASR/게이트웨이 방어 설정

🎯 학습 목표

조직 환경에서 스피어피싱을 방어하기 위한 GPO(그룹 정책), ASR 규칙, 이메일 게이트웨이 설정을 구체적으로 학습합니다.

1. GPO: Office 매크로 비활성화

가장 확실한 방어는 인터넷에서 다운로드한 Office 파일의 매크로를 전면 차단하는 것입니다. Windows는 인터넷에서 다운로드한 파일에 Zone.Identifier (Mark of the Web) 태그를 추가하므로, 이를 기반으로 매크로를 선택적으로 차단할 수 있습니다.

# GPO 경로: 사용자 구성 → 관리 템플릿 → Microsoft Word → 보안
# "인터넷에서 가져온 Office 파일에서 매크로 실행 차단"

Registry Key:  HKCU\Software\Policies\Microsoft\Office\16.0\Word\Security
Value Name:    blockcontentexecutionfrominternet
Value:         1 (Enabled)

# PowerShell로 일괄 적용 (Word + Excel + PowerPoint)
$apps = @('Word','Excel','PowerPoint')
foreach ($app in $apps) {
    $path = "HKCU:\Software\Policies\Microsoft\Office\16.0\$app\Security"
    New-Item -Path $path -Force | Out-Null
    Set-ItemProperty -Path $path -Name "blockcontentexecutionfrominternet" -Value 1
}

2. ASR 규칙 전체 활성화

# 피싱 방어용 ASR 규칙 4종 Block 모드 일괄 활성화
$rules = @(
    "D4F940AB-401B-4EFC-AADC-AD5F3C50688A",  # Office 자식 프로세스 차단
    "3B576869-A4EC-4529-8536-B80A7769E899",  # 실행 콘텐츠 생성 차단
    "92E97FA1-2EDF-4476-BDD6-9DD0B4DDDC7B",  # Win32 API 호출 차단
    "5BEB7EFE-FD9A-4556-801D-275E5FFC04CC"   # 난독화 스크립트 차단
)
$actions = @("Enabled","Enabled","Enabled","Enabled")

Set-MpPreference `
    -AttackSurfaceReductionRules_Ids $rules `
    -AttackSurfaceReductionRules_Actions $actions

# 적용 확인
Get-MpPreference | Select-Object `
    AttackSurfaceReductionRules_Ids,
    AttackSurfaceReductionRules_Actions

3. 이메일 게이트웨이 첨부파일 정책

• 차단 확장자: .exe, .scr, .bat, .cmd, .vbs, .js, .wsf, .hta, .ps1

• 경고 확장자: .docm, .xlsm, .pptm (매크로 포함 문서)

• 샌드박스 대상: .doc, .docx, .xls, .xlsx, .pdf, .zip, .rar

• URL 재작성: 본문 내 URL을 Safe Links로 래핑하여 클릭 시 검사

4. PowerShell Constrained Language Mode

# Constrained Language Mode 활성화 (GPO 또는 AppLocker)
# 제한 모드에서는 .NET 직접 호출, COM 객체, Add-Type 등이 차단됨

# 현재 모드 확인
$ExecutionContext.SessionState.LanguageMode
# 결과: ConstrainedLanguage (제한 모드) 또는 FullLanguage (전체 모드)

# 제한 모드에서 차단되는 예시
PS> [System.Net.WebClient]::new().DownloadFile(...)
ERROR: Cannot create type. Only core types are supported in this language mode.

💡 배포 순서 권장

① DMARC p=reject → ② ASR Audit 모드(1주 모니터링) → ③ ASR Block 모드 전환 → ④ GPO 매크로 차단 → ⑤ Constrained Language Mode. 단계별로 적용하고 오탐(False Positive)을 확인한 후 다음 단계로 진행합니다.
