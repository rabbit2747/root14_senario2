T1586.003
클라우드 계정 탈취

기존 클라우드 서비스 계정(AWS, Azure, GCP 등)을 탈취하여 공격 인프라로 활용하는 기법을 학습합니다.

☁️ Chapter 1 — 클라우드 계정 탈취 개요

공격자는 기존 클라우드 서비스 계정을 탈취하여 공격 인프라로 활용합니다. 새로운 계정을 생성하는 것보다 기존 계정을 사용하면 평판이 높고, 결제 정보가 이미 등록되어 있으며, 보안 팀의 의심을 덜 받습니다.

탈취 대상 클라우드 서비스
  • - AWS (EC2, S3, Lambda)
  • - Microsoft Azure (VM, Storage, Functions)
  • - Google Cloud Platform (Compute, Storage)
  • - DigitalOcean, Linode, Vultr (VPS)
탈취된 계정의 악용
  • - C2 서버 호스팅 (합법 클라우드 IP 대역)
  • - 피싱 인프라 구축 (높은 도메인 평판)
  • - 암호화폐 채굴 (피해자 비용)
  • - 데이터 유출 스테이징 (S3/Blob Storage)

⚡ Chapter 2 — 공격 기법

자격증명 탈취 (Credential Theft)

GitHub 리포지토리에 실수로 커밋된 AWS Access Key, .env 파일에 하드코딩된 API 키, Infostealer에 의해 탈취된 브라우저 세션 쿠키를 통해 클라우드 콘솔에 접근합니다. 2024년 기준 AWS 키 유출은 GitHub에서 시간당 수백 건 발생합니다.

피싱/AiTM 공격

Microsoft 365/Azure AD 로그인 페이지를 피싱하여 MFA 토큰까지 실시간 탈취하는 AiTM(Adversary-in-the-Middle) 공격입니다. EvilGinx2, Modlishka 같은 프레임워크가 MFA 우회를 자동화합니다.

OAuth 토큰 악용

악성 OAuth 앱을 통해 사용자가 권한을 부여하면, 비밀번호 없이도 클라우드 리소스에 접근할 수 있습니다. 토큰은 비밀번호 변경이나 MFA 추가로도 무효화되지 않아 지속적인 접근이 가능합니다.

🛡️ Chapter 3 — 탐지와 방어

키 관리 및 보호
  • - AWS Secrets Manager / Azure Key Vault 사용
  • - Git pre-commit hooks로 키 유출 방지
  • - IAM 키 자동 회전 (90일 주기)
  • - GitHub Secret Scanning 활성화
접근 제어 강화
  • - MFA 필수 적용 (FIDO2/하드웨어 키)
  • - 조건부 접근 정책 (IP/위치 기반)
  • - 최소 권한 원칙 (Least Privilege)
  • - OAuth 앱 허용 목록 관리
이상 행위 탐지

AWS GuardDuty, Azure Sentinel, GCP Security Command Center 같은 클라우드 네이티브 SIEM을 활용하여 비정상적인 API 호출, 새로운 지역에서의 로그인, 대량 리소스 생성 등을 탐지합니다. CloudTrail/Activity Log를 항상 활성화하고 외부 SIEM으로 전송해야 합니다.

# AWS GuardDuty 이상 행위 알림 예시

Finding Type: UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS

Severity: HIGH

Description: IAM credentials from EC2 instance i-0abc123 are being used from IP 45.33.x.x (outside AWS)

Action: ec2:RunInstances (10 instances in ap-northeast-2)

Recommended: Rotate credentials, investigate instance, enable IMDSv2
