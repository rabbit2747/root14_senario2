T1499: Endpoint Denial of Service

Impact

Denial of Service

서버를 과부하 시켜 정상 사용자의 접근을 차단하는 공격

#1. 서비스 거부(DoS/DDoS)란?

🌊 ➜ 🖥️ ➜ 💥 ➜ 🚫

"고속도로에 차를 가득 채워 다른 차가 못 지나가게"

서비스 거부 공격은 서버나 애플리케이션에 감당할 수 없는 양의 요청을 보내어 정상 사용자가 서비스를 이용하지 못하게 만드는 공격입니다. 단일 출처에서 공격하면 DoS, 수천~수백만 대의 봇넷에서 동시에 공격하면 DDoS입니다.

🌐
L7 (Application)
HTTP Flood, Slowloris, API 남용
📡
L4 (Transport)
SYN Flood, UDP Flood
💣
L3 (Network)
ICMP Flood, 증폭 공격

#2. 공격 유형 분석

HTTP Flood (L7)

정상적인 HTTP 요청을 대량으로 보내 웹서버의 처리 능력을 고갈시킵니다. 정상 트래픽과 구분이 어려워 방어가 까다롭습니다. 특히 DB 쿼리가 무거운 검색 API를 표적으로 하면 적은 요청으로도 서버를 마비시킬 수 있습니다.

Slowloris (L7)

HTTP 요청을 아주 천천히 보내 서버의 연결 풀(Connection Pool)을 소진시킵니다. 대역폭을 거의 사용하지 않으므로 탐지가 어렵습니다. 단일 PC로도 웹서버를 무력화할 수 있는 효율적인 공격입니다.

# Application-layer DoS 의사코드 (HTTP Flood)
for i in range(100000):
# 무거운 검색 쿼리로 DB 부하 유발
requests.get("https://target.com/search?q=" + random_string(50))
# 서버: CPU 100%, 메모리 고갈, 응답 불가

탐지 방법

  • - 트래픽 이상 탐지: 평소 대비 급증 모니터링
  • - Rate Limiting: IP별 요청 횟수 제한
  • - 응답 시간 모니터링: 지연 시간 급증 경보

방어 전략

  • - CDN/DDoS 방어 서비스 (Cloudflare, AWS Shield)
  • - WAF + Rate Limiting 적용
  • - Auto Scaling으로 트래픽 분산
