01

Purple Team 운영 개론

🎯 학습 목표

Purple Team의 개념, Red/Blue Team과의 관계, 스피어피싱 방어 평가를 위한 Purple Team Exercise 설계 방법을 학습합니다.

Purple Team이란?

Purple Team은 Red Team(공격)과 Blue Team(방어)이 실시간으로 협력하여 탐지 능력을 개선하는 접근입니다. Red Team이 공격을 실행하면, Blue Team이 즉시 탐지 여부를 확인하고, 미탐지 시 즉석에서 규칙을 개선합니다.

Red Team

공격 시뮬레이션

ATT&CK 기법 실행

우회 기법 적용

Purple Team

실시간 협력

탐지 갭 식별

즉시 개선

Blue Team

탐지 모니터링

규칙 튜닝

인시던트 대응

Purple Team Exercise 프레임워크

═══ T1566.001 Purple Team Exercise 계획서 ═══

Phase 1: 사전 준비 (D-7)
  - ATT&CK Navigator에서 T1566.001 관련 기법 매핑
  - 현재 탐지 규칙 인벤토리 수집 (Sigma/YARA/ASR)
  - Atomic Red Team 테스트 케이스 선정

Phase 2: 테이블탑 (D-1)
  - Red: 공격 시나리오 브리핑 (5단계 공격 체인)
  - Blue: 예상 탐지 포인트 명시
  - Purple: 탐지 기대치 합의 (Expected Detection Matrix)

Phase 3: 실행 (D-Day)
  - Red: Atomic Red Team T1566.001 테스트 실행
  - Blue: SIEM에서 실시간 탐지 확인
  - Purple: 탐지/미탐지 실시간 기록

Phase 4: 후속 조치 (D+1~7)
  - 미탐지 항목 → 새 Sigma 규칙 작성
  - Detection Coverage 업데이트
  - 리포트 작성 및 경영진 보고

💡 핵심 포인트

전통적 Red Team은 "침투 성공"이 목표이고, Blue Team은 "탐지/차단"이 목표입니다. Purple Team의 목표는 "탐지 갭을 제로로 줄이는 것"입니다. 경쟁이 아닌 협력 관계입니다.

02

Red Team 피싱 시뮬레이션

🎯 학습 목표

Red Team이 Purple Team Exercise에서 수행하는 단계별 피싱 시뮬레이션 절차와 Atomic Red Team 테스트 활용법을 학습합니다.

Atomic Red Team: T1566.001 테스트

Atomic Red Team은 MITRE ATT&CK 기법을 작은 단위의 테스트(Atomic Test)로 분해하여, 각 기법이 탐지되는지 검증하는 오픈소스 프레임워크입니다.

# Atomic Red Team 설치 및 T1566.001 테스트 실행
Install-Module -Name Invoke-AtomicRedTeam -Force
Import-Module Invoke-AtomicRedTeam

# 사용 가능한 T1566.001 테스트 목록 확인
Invoke-AtomicTest T1566.001 -ShowDetailsBrief

# Test #1: Download Phishing Attachment - VBA Macro
# Test #2: Word spawning cmd.exe
# Test #3: PowerShell download cradle from Office macro

# 특정 테스트 실행
Invoke-AtomicTest T1566.001 -TestNumbers 1,2,3

# 테스트 후 정리 (Clean-up)
Invoke-AtomicTest T1566.001 -TestNumbers 1,2,3 -Cleanup

Red Team 체크리스트

✅ 테스트 전 Blue Team에 시간대 공유 (Purple 원칙)

✅ 각 테스트 단계별 타임스탬프 기록 (초 단위)

✅ 기본 공격 → 난독화 공격 → LOLBin 공격 순서로 난이도 상승

✅ 테스트 완료 후 반드시 Cleanup 실행 (잔여 아티팩트 제거)

✅ 각 단계의 Expected Detection 문서화

⚠️ 운영 규칙

Purple Team Exercise는 반드시 경영진 승인과 법적 동의서(Rules of Engagement)가 필요합니다. 프로덕션 환경에서 실행 시 업무 영향도를 사전 평가해야 합니다.

04

CVE-2021-40444 MSHTML 분석

🎯 학습 목표

CVE-2021-40444(MSHTML 원격 코드 실행) 취약점의 공격 메커니즘과 스피어피싱에서의 활용 방식, 탐지 전략을 분석합니다.

취약점 개요

CVE: CVE-2021-40444

CVSS: 8.8 (High)

영향: MSHTML (Internet Explorer 렌더링 엔진) 원격 코드 실행

핵심: 매크로 없이 Office 문서를 열기만 해도 코드 실행 가능

패치: 2021년 9월 Microsoft 보안 업데이트

공격 체인

═══ CVE-2021-40444 공격 흐름 ═══

1. 공격자가 악성 .docx 전송 (매크로 불필요!)
2. 사용자가 문서 열기 → Word가 OLE Object 로드
3. OLE Object 내 URL → MSHTML(IE 엔진)이 원격 HTML 렌더링
4. HTML 내 JavaScript → ActiveX 컨트롤 → .cab 다운로드
5. .cab 내 .dll → 사이드로딩으로 코드 실행
6. 결과: 사용자 상호작용 = "파일 열기"만으로 RCE 달성

핵심 차이점:
기존 T1566.001: 매크로 "콘텐츠 사용" 클릭 필요
CVE-2021-40444: 파일 열기만 하면 자동 실행 (0-click에 가까움)

탐지 전략

• Sysmon ID 1: WINWORD.EXE → control.exe 또는 rundll32.exe 자식 프로세스

• Sysmon ID 3: WINWORD.EXE에서 직접 외부 HTTP 연결

• Sysmon ID 11: %TEMP%\*.cab 파일 생성

• YARA: .docx 내 relationship 파일에서 mhtml: URL 패턴 탐지

⚠️ 교훈

이 CVE는 "매크로 차단이면 안전하다"는 가정을 무너뜨렸습니다. ASR + 매크로 차단만으로는 불충분하며, 문서 내 OLE 객체와 외부 리소스 로드도 모니터링해야 합니다.

05

CVE-2022-30190 Follina 분석

🎯 학습 목표

CVE-2022-30190(Follina)의 ms-msdt: 프로토콜 핸들러 악용 방식과, 스피어피싱 첨부파일에서의 활용 및 탐지 방법을 분석합니다.

Follina 공격 메커니즘

═══ Follina (CVE-2022-30190) 공격 체인 ═══

1. 악성 .docx 파일 (매크로 없음)
2. 문서 내 OLE Object → 외부 HTML 참조
3. HTML 내 JavaScript → ms-msdt: 프로토콜 핸들러 호출
4. MSDT(Microsoft Support Diagnostic Tool) 실행
5. MSDT가 PowerShell 페이로드 실행
6. 결과: 매크로/ActiveX 없이 코드 실행

핵심: ms-msdt: URI 스킴이 MSDT를 호출하고,
      MSDT의 IT_BrowseForFile 매개변수에 PowerShell 삽입

Sysmon 탐지 포인트:
Event ID 1: WINWORD.EXE → msdt.exe (비정상 자식 프로세스)
Event ID 1: msdt.exe → sdiagnhost.exe → powershell.exe
Event ID 3: powershell.exe → 외부 C2 연결

탐지 Sigma 규칙

title: Follina MSDT Exploitation via Office Application
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        ParentImage|endswith:
            - '\WINWORD.EXE'
            - '\EXCEL.EXE'
        Image|endswith: '\msdt.exe'
    condition: selection
level: critical
tags:
    - attack.initial_access
    - attack.t1566.001
    - cve.2022.30190

완화 조치

• 레지스트리: ms-msdt 프로토콜 핸들러 비활성화 (reg delete HKCR\ms-msdt)

• ASR: "Office 앱의 자식 프로세스 생성 차단" 규칙 적용

• 패치: 2022년 6월 보안 업데이트 적용

CVE-2023-23397 Outlook 분석

🎯 학습 목표

CVE-2023-23397(Outlook NTLM 릴레이)의 0-click 공격 메커니즘과, 이메일 수신만으로 인증 정보가 탈취되는 과정을 분석합니다.

0-Click 공격의 정점

CVSS 9.8 (Critical)

사용자가 이메일을 열지 않아도, Outlook이 알림음 리소스를 로드하는 순간 NTLM 해시가 공격자 서버로 전송됩니다. 진정한 0-click 공격입니다.

═══ CVE-2023-23397 공격 흐름 ═══

1. 공격자가 악성 캘린더 초대/이메일 발송
2. 메일에 PidLidReminderFileParameter 속성 포함
   값: \\attacker-server\share\alarm.wav (UNC 경로)
3. Outlook이 알림 처리 시 UNC 경로 접근 시도
4. Windows가 자동으로 NTLM 인증 수행
5. 공격자 서버에서 NTLM 해시 캡처
6. Pass-the-Hash 또는 NTLM 릴레이로 인증 탈취

사용자 상호작용: 없음 (0-click)
Outlook 미리보기 창에서도 트리거됨

탐지 및 완화

• 네트워크: 내부→외부 SMB(445)/WebDAV 아웃바운드 트래픽 차단

• Sysmon ID 3: OUTLOOK.EXE → 외부 IP:445 연결 탐지

• GPO: NTLM 인증 제한 (Kerberos only 정책)

• Microsoft 스크립트: CVE-2023-23397 검사 스크립트로 기존 메일 감사

💡 핵심 교훈

T1566.001의 전통적 방어(매크로 차단, 사용자 교육)는 이 CVE에 무력합니다. 네트워크 계층 방어(SMB 아웃바운드 차단)와 신속한 패치 관리가 0-click 취약점의 유일한 방어선입니다.

07

제로데이 연구 방법론

🎯 학습 목표

Office 문서 파서의 공격 표면(Attack Surface)을 분석하는 방법론과, 제로데이 취약점 연구의 체계적 접근법을 학습합니다.

Office 문서의 공격 표면

═══ Office 문서 파싱 시 실행되는 컴포넌트 ═══

.docx/.xlsx 열기
    │
    ├─ XML 파서 (System.Xml)
    │   └─ XXE 취약점 가능성
    │
    ├─ OLE Object 핸들러
    │   ├─ ActiveX 컨트롤 로드
    │   ├─ DDE (Dynamic Data Exchange)
    │   └─ 외부 리소스 참조 (URL)
    │
    ├─ OOXML Relationship 처리
    │   └─ 외부 HTML/RTF 참조
    │       └─ MSHTML 렌더링 (CVE-2021-40444)
    │
    ├─ 프로토콜 핸들러 호출
    │   └─ ms-msdt: (CVE-2022-30190)
    │   └─ ms-search: / ms-officecmd:
    │
    └─ 미디어/리소스 로드
        └─ UNC 경로 → NTLM 인증 (CVE-2023-23397)

취약점 연구 5단계

1

공격 표면 매핑

파일 형식 사양(OOXML, OLE2)을 분석하여 파서가 처리하는 모든 입력 벡터를 목록화

2

퍼징 (Fuzzing)

변형된 입력 파일을 대량 생성하여 크래시/비정상 동작 유발 (AFL, WinAFL)

3

근본 원인 분석 (Root Cause)

크래시 트리거의 근본 원인(메모리 손상, 타입 혼동 등) 분석

4

익스플로잇 개발

코드 실행까지 체인 완성 (RIP 제어 → ROP → 셸코드)

5

책임 있는 공개

벤더 보고(MSRC) → 패치 개발 대기 → CVE 할당 → 공개 (Coordinated Disclosure)

09

위협 인텔리전스 통합

🎯 학습 목표

CTI(Cyber Threat Intelligence)를 탐지 파이프라인에 통합하여, 스피어피싱 캠페인을 선제적으로 탐지하는 방법을 학습합니다.

CTI 피라미드 (David Bianco)

TTPs (전술·기법·절차)

가장 가치 높은 인텔 → Sigma/YARA 규칙으로 운용화

도구 (Tools)

공격자 도구 시그니처 → YARA 규칙

네트워크/호스트 아티팩트

레지스트리 키, 파일 경로, User-Agent

도메인/IP

C2 도메인, 피싱 인프라 IP → 방화벽/DNS 차단

해시 (Hash)

파일 해시(MD5/SHA256) → 가장 쉽게 우회 가능

STIX/TAXII를 통한 자동화

STIX(Structured Threat Information eXpression)는 위협 정보의 표준 형식이고, TAXII(Trusted Automated eXchange)는 이를 자동으로 교환하는 프로토콜입니다. MISP, OpenCTI 등의 CTI 플랫폼에서 STIX/TAXII로 IOC를 수신하여 SIEM에 자동 반영합니다.

💡 핵심 포인트

피라미드 상단(TTP)으로 갈수록 공격자가 변경하기 어렵고, 탐지 가치가 높습니다. 전문가는 해시/IP 차단에 머무르지 않고, TTP 수준의 탐지 규칙(Sigma)을 작성하여 공격자의 도구/인프라 변경에도 대응합니다.
