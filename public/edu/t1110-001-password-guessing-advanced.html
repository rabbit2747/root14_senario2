#1. 분산 무차별 대입 공격

🌐

봇넷과 프록시 기반 분산 공격

고급 공격자는 단일 IP가 아닌 수천 개의 봇넷 또는 프록시 서버를 통해 비밀번호 추측을 분산시킵니다. 각 IP에서 소수의 시도만 하므로 IP 기반 임계값 탐지를 우회합니다. APT28은 Kubernetes 클러스터에서 수천 개의 IP를 순환하며 공격했습니다.

distributed_attack.py
ADVANCED · python
⚠️ 교육 목적 의사 코드 — 실제 구현 불가
# 분산 비밀번호 추측 공격 구조 (의사 코드)
class DistributedBruteForce:
def __init__(self, proxy_list, target):
self.proxies = load_proxies(proxy_list)
self.delay = 60 # IP당 시도 간격 (초)
def spray_attack(self, users, password):
for user in users:
proxy = self.proxies.rotate() # IP 순환
result = try_login(user, password, proxy)
time.sleep(self.delay) # 탐지 회피
# 회피: IP당 1~2회, 계정당 30분 간격, 업무시간대 시도

⚠️ 분산 공격의 탐지 난이도

분산 비밀번호 공격은 단일 IP 기반 탐지를 무력화합니다. 방어자는 IP가 아닌 '대상 계정' 관점에서 실패를 집계하고, GeoIP 이상, 시간대 패턴, User-Agent 이상 등 복합 지표를 활용해야 합니다.

#2. Credential Stuffing 기법

🗃️

유출된 자격증명의 재사용 공격

Credential Stuffing은 다른 서비스에서 유출된 '이메일:비밀번호' 쌍을 대상 서비스에 대입하는 공격입니다. 사용자의 약 65%가 여러 서비스에서 동일한 비밀번호를 사용하므로, 한 곳에서 유출되면 다른 서비스도 위험합니다.

Credential Stuffing vs Password Spraying

구분Credential StuffingPassword Spraying
입력 데이터유출된 이메일:비밀번호 쌍사용자 목록 + 공통 비밀번호
비밀번호 수계정당 1개 (유출된 것)전체에 동일 1~2개씩
성공률0.1~2%대규모 조직에서 높음
대표 도구Sentry MBA, OpenBulletSpray, Ruler

#3. Password Spraying 탐지 전략

🔍

스프레잉 공격의 탐지 어려움

Password Spraying은 단일 비밀번호를 수백~수천 개의 계정에 시도합니다. 계정당 1회만 시도하므로 계정 잠금이 발생하지 않습니다. 탐지 핵심: 짧은 시간에 다수의 서로 다른 계정에서 동일한 실패 패턴이 나타나는지 확인.

azure_spray_detection.kql
ADVANCED · kusto
🔎 Microsoft Sentinel KQL — 방어 목적
SigninLogs
| where ResultType == '50126' // 잘못된 비밀번호
| where TimeGenerated > ago(1h)
| summarize
FailedAccounts = dcount(UserPrincipalName),
AttemptCount = count()
by IPAddress, bin(TimeGenerated, 10m)
| where FailedAccounts > 5 and AttemptCount > 10
| sort by AttemptCount desc

#4. SIEM 상관 분석 규칙

📊

다차원 상관 분석 (Correlation)

단순 임계값 기반 탐지는 분산 공격에 취약합니다. SIEM 상관 분석은 여러 데이터 소스를 결합하여 복합적인 공격 패턴을 탐지합니다. 핵심: 다수 계정 동시 실패, GeoIP 이상, 비업무 시간대, 알려진 악성 IP 매칭.

splunk_correlation.spl
ADVANCED · splunk
index=wineventlog EventCode=4625
| bucket _time span=10m
| stats
dc(TargetUserName) as unique_accounts,
dc(IpAddress) as unique_ips,
count as total_failures by _time
| where unique_accounts > 5 AND total_failures > 20
| eval risk_score = unique_accounts * total_failures / unique_ips
| where risk_score > 50

#6. 엔터프라이즈 방어: MFA와 FIDO2

🔐

다중 인증(MFA)의 종류와 강도

MFA는 비밀번호 추측 공격에 대한 가장 효과적인 방어입니다. MFA 강도 순위: SMS OTP < 앱 기반 TOTP < 푸시 알림 < FIDO2 물리 키. FIDO2/WebAuthn은 피싱과 중간자 공격에도 면역입니다.

MFA 방식별 보안 강도 비교

MFA 방식보안 강도피싱 저항편의성
SMS OTP🟡 중간SIM 스와핑 취약🟢 높음
TOTP (Authenticator)🟢 양호시드 유출 취약🟡 중간
Push 알림🟢 양호MFA Fatigue 가능🟢 높음
FIDO2/WebAuthn🔴 최상피싱 면역🟡 중간

⚠️ MFA Fatigue 공격 주의

공격자가 MFA 푸시 알림을 반복 전송하여 사용자가 지쳐서 승인하게 만드는 공격입니다. 2022년 Uber 해킹에서 사용되었습니다. 대응: Number Matching(숫자 확인) MFA 정책 적용.

#7. 적응형 인증과 Zero Trust

🧠

적응형 인증 (Adaptive Authentication)

적응형 인증은 사용자의 행동 패턴, 위치, 디바이스, 시간대 등을 분석하여 위험도를 실시간 평가합니다. 평소와 다른 패턴 감지 시 추가 인증을 요구하거나 접근을 차단합니다.

Zero Trust 인증 아키텍처

  [사용자]                    [Zero Trust Gateway]
     |                           |
     |-- 1 아이덴티티 확인 -->  |  Identity Provider
     |     (ID/PW + MFA)         |  (Azure AD, Okta)
     |                           |
     |-- 2 디바이스 검증 --->   |  Device Trust
     |     (EDR 상태, 패치)      |  (Intune, Jamf)
     |                           |
     |-- 3 컨텍스트 평가 --->   |  Risk Engine
     |     (위치, 시간, 행동)    |  (위험 점수 계산)
     |                           |
     |                  위험 점수 < 임계값?
     |                    |-- Yes --> 접근 허용
     |                    +-- No ---> 추가 인증 / 차단

#Q. 종합 퀴즈

Q1. 분산 비밀번호 추측이 IP 기반 탐지를 우회하는 원리는?

💡 분산 공격은 수천 개의 IP를 순환하며 각 IP에서 1~2회만 시도하여 IP당 임계값에 도달하지 않습니다.

Q2. Credential Stuffing과 Password Spraying의 핵심 차이는?

💡 Credential Stuffing은 유출된 이메일:비밀번호 쌍을 재사용, Password Spraying은 공통 비밀번호 하나를 다수 계정에 시도합니다.

Q3. FIDO2/WebAuthn이 비밀번호 추측에 면역인 이유는?

💡 FIDO2는 공개키-개인키 쌍 사용. 개인키는 보안키에 저장, 추출 불가. 추측할 비밀번호 자체가 없습니다.

Q4. MFA Fatigue 공격의 가장 효과적인 대응책은?

💡 Number Matching은 화면 숫자를 앱에서 입력해야 승인. 단순 '승인' 불가하므로 Fatigue 공격 방어.

Q5. Password Spraying SIEM 탐지의 핵심 지표는?

💡 Spraying은 하나의 비밀번호를 많은 계정에 시도. 전체 조직 수준의 동시 실패 패턴이 핵심입니다.

Q6. 공격 성공 시 가장 우선적 조치는?

💡 탈취 계정은 공격자가 즉시 악용 가능하므로, 비활성화 및 세션 종료가 최우선입니다.

Q7. 적응형 인증이 전통적 인증보다 우수한 점은?

💡 적응형 인증은 IP 위치, 디바이스, 시간대, 행동 패턴을 분석하여 위험을 동적으로 관리합니다.

Q8. Zero Trust 접근 결정에 영향을 미치지 않는 요소는?

💡 Zero Trust는 아이덴티티+디바이스+컨텍스트를 평가합니다. 물리적 케이블 종류는 무관합니다.
