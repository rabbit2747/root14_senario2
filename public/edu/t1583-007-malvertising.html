악성 광고 인프라

합법적인 광고 네트워크를 악용하여 악성코드를 배포하는 Malvertising 인프라 구축 기법을 학습합니다.

📢 Chapter 1 — 악성 광고(Malvertising) 개요

Malvertising은 합법적인 광고 네트워크를 통해 악성 콘텐츠를 배포하는 기법입니다. 공격자는 광고 계정을 생성하고, 합법적으로 보이는 광고를 구매하여 대규모 웹사이트의 방문자를 악성코드에 노출시킵니다.

Malvertising 유형
  • - Pre-click: 광고 로드만으로 Exploit 실행
  • - Post-click: 광고 클릭 후 악성 사이트 리다이렉트
  • - 강제 리다이렉트: 사용자 동의 없이 자동 이동
  • - 가짜 경고: "바이러스 감지" 팝업으로 유도
주요 광고 플랫폼 악용
  • - Google Ads (검색 광고 최상단 노출)
  • - Facebook/Meta Ads (타겟팅 광고)
  • - Programmatic Ad Networks (RTB 자동 입찰)
  • - Native Ad Platforms (콘텐츠 추천형)

⚡ Chapter 2 — 광고 네트워크 악용

Google Ads 악용 (검색 결과 상위 노출)

공격자는 합법 소프트웨어 이름으로 Google 검색 광고를 구매합니다. "Slack download", "Zoom installer" 같은 키워드에 입찰하면 검색 결과 최상단에 노출됩니다. 광고 URL은 정상처럼 보이지만 실제로는 트로이 목마가 포함된 설치 파일로 연결됩니다.

프로그래매틱 광고 악용 (RTB)

Real-Time Bidding(실시간 입찰) 시스템에서 광고가 자동으로 매칭되므로, 웹사이트 운영자가 어떤 광고가 표시되는지 직접 통제하기 어렵습니다. 공격자는 합법 광고 소재로 심사를 통과한 뒤, 승인 후 악성 콘텐츠로 교체(Ad Swapping)합니다.

광고 계정 인프라

공격자는 도난 신용카드 또는 가상 카드로 광고 계정을 생성합니다. 합법 사업자로 가장한 서류를 제출하고, VPN/프록시로 위치를 위장합니다. 계정이 차단되면 새 계정으로 즉시 전환하는 "버너 계정" 전략을 사용합니다.

🛡️ Chapter 3 — 탐지와 방어

광고 차단 기반 방어
  • - 기업용 광고 차단기 배포 (uBlock Origin 등)
  • - DNS 기반 광고 차단 (Pi-hole, AdGuard DNS)
  • - 브라우저 격리(RBI)를 통한 광고 샌드박싱
  • - 신뢰할 수 없는 도메인 자동 차단
조직 차원 대응
  • - 소프트웨어 다운로드 정책 수립 (공식 사이트만 허용)
  • - 사용자 보안 인식 교육 (가짜 광고 구별법)
  • - 신규 등록 도메인(NRD) 30일 차단
  • - AppLocker/WDAC로 비인가 실행 파일 차단
광고 플랫폼 대응

Google은 2024년 광고주 신원 확인 프로그램을 강화하고 AI 기반 악성 광고 탐지 시스템을 도입했습니다. 그러나 공격자들은 지속적으로 탐지를 우회하는 새로운 기법을 개발하고 있어, 기술적 방어와 사용자 인식 교육을 병행해야 합니다.

# Group Policy — 소프트웨어 다운로드 제한 정책

Computer Configuration → Administrative Templates → Windows Components

→ SmartScreen: Block unrecognized apps → Enabled

→ AppLocker: Allow only signed applications → Enabled

→ WDAC: Block apps from Internet zone → Enabled
