#1. 비대칭 암호화란? C2에서의 악용

🔑 ➜ 🔐 ➜ 📡 ➜ 🔓

"공개키로 잠그고, 개인키로만 풀 수 있는 비밀 통신"

비대칭 암호화는 공개키(Public Key)와 개인키(Private Key) 두 개의 키를 사용합니다. 공개키로 암호화한 메시지는 개인키로만 복호화할 수 있습니다. 해커는 이 원리를 이용해 C2 서버의 공개키로 명령을 암호화하여 전송하므로, 네트워크에서 패킷을 가로채도 내용을 읽을 수 없습니다.

왜 비대칭 암호화인가?

대칭 암호화는 같은 키를 공유해야 하므로 키 교환 시 노출 위험이 있습니다. 반면 비대칭 암호화는 공개키를 자유롭게 배포하되 개인키만 안전하게 보관하면 됩니다. 해커는 악성코드에 C2 서버의 공개키를 하드코딩하여 역분석(리버싱)으로도 통신을 복호화할 수 없게 만듭니다.

🔑
키 쌍 생성
RSA 2048/4096 또는 ECC 키 쌍 생성
🛡️
암호화 통신
공개키로 암호화, 개인키로만 복호화
🚫
감청 불가
네트워크 캡처로도 내용 해독 불가

#2. RSA/ECC 기반 C2 채널 구축

RSA 기반 C2

악성코드에 C2 서버의 RSA 공개키를 내장합니다. 감염 PC는 수집한 데이터를 공개키로 암호화하여 전송합니다. RSA 2048비트 이상이면 현재 기술로 해독이 불가능합니다. 단점으로 데이터 크기가 커지므로 실제로는 AES 키를 RSA로 교환하는 하이브리드 방식을 씁니다.

ECC 기반 C2

타원곡선 암호(ECC)는 RSA보다 짧은 키로 동일한 보안 강도를 제공합니다. ECC 256비트 = RSA 3072비트 수준입니다. 키가 짧으므로 악성코드 크기가 줄고, 통신 오버헤드도 적어 모바일 악성코드나 IoT 봇넷에서 선호됩니다.

실전 사례: 하이브리드 암호화 C2

실제 APT 그룹은 RSA/ECC + AES 하이브리드를 사용합니다. 세션마다 랜덤 AES 키를 생성하고, 이를 RSA 공개키로 암호화하여 전송한 뒤, 이후 통신은 AES로 수행합니다. TLS 핸드셰이크와 동일한 원리입니다.

# 하이브리드 암호화 C2 핸드셰이크
1. 악성코드 → C2: RSA_Encrypt(AES_Session_Key)
2. C2 → 악성코드: AES_Encrypt(Command, Session_Key)
3. 악성코드 → C2: AES_Encrypt(Result, Session_Key)
# TLS와 동일한 원리 — 키 교환은 RSA, 데이터는 AES
