#1. 레지스트리 Run 키 분석 코드

🔧

PowerShell로 자동 실행 항목 열거

PowerShell을 사용하면 모든 자동 실행 레지스트리 키를 프로그래밍 방식으로 열거할 수 있습니다. Get-ItemProperty 명령으로 HKLM과 HKCU의 Run 키 값을 읽고, 등록된 프로그램의 경로, 서명 상태, 파일 해시를 확인하여 의심스러운 항목을 식별합니다.

enum_autorun.ps1
powershell
⚠️ 교육 목적 코드 — 방어 분석용
# 레지스트리 Run 키 자동 실행 항목 열거
# HKLM과 HKCU의 Run/RunOnce 키를 모두 확인
$runKeys = @(
'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run',
'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce',
'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run',
'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce'
)
foreach ($key in $runKeys) {
Write-Host "[*] Checking: $key" -ForegroundColor Cyan
if (Test-Path $key) {
$props = Get-ItemProperty -Path $key
$props.PSObject.Properties | Where-Object {
$_.Name -notlike 'PS*'
} | ForEach-Object {
Write-Host " Name: $($_.Name)" -ForegroundColor Yellow
Write-Host " Value: $($_.Value)" -ForegroundColor Red
}
}
}

#2. 공격자의 레지스트리 조작 기법

🎭

reg.exe와 PowerShell을 이용한 지속성 확보

공격자는 시스템 내장 도구를 사용하여 레지스트리를 조작합니다. reg.exe는 명령줄에서 직접 레지스트리를 수정하는 Windows 내장 도구이며, PowerShell의 Set-ItemProperty/New-ItemProperty도 동일한 역할을 합니다. Living-off-the-Land 기법으로 추가 도구 없이 지속성을 확보합니다.

attacker_persistence.bat
batch
⚠️ 교육 목적 코드 — 공격 패턴 분석용
REM 공격자가 사용하는 Run 키 등록 방법들
REM 모두 시스템 내장 도구 사용 (LotL)
REM 방법 1: reg.exe (가장 일반적)
reg add HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run ^
/v "WindowsUpdate" /t REG_SZ ^
/d "C:\Users\Public\svchost.exe" /f
REM 방법 2: PowerShell (인코딩된 명령)
powershell -c "Set-ItemProperty -Path ^
'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run' ^
-Name 'SecurityHealth' -Value 'C:\temp\payload.exe'"
REM 방법 3: Startup 폴더에 LNK 파일 생성
copy malware.lnk "%APPDATA%\Microsoft\Windows\
Start Menu\Programs\Startup\update.lnk"

⚠️ 정상 프로그램과 악성코드 구별 포인트

악성코드는 보통 다음 패턴을 보입니다: ① 정상 Windows 프로세스 이름을 사칭 (svchost.exe, csrss.exe). ② 비정상적 경로에서 실행 (C:\Users\Public, %TEMP%). ③ 디지털 서명이 없거나 유효하지 않음. ④ 파일 생성 시간이 최근이며 원래 시스템에 없던 파일.

#3. Autoruns 도구 활용

🔌

Sysinternals Autoruns — 종합 자동 실행 분석

Mark Russinovich가 개발한 Autoruns는 Windows 시스템의 모든 자동 실행 위치를 한눈에 보여주는 도구입니다. 레지스트리 Run 키, Startup 폴더 외에도 서비스, 드라이버, 스케줄 작업, WMI 이벤트, DLL 로드 등 수십 개의 자동 실행 위치를 검사합니다. 비서명 항목을 강조 표시하여 의심스러운 엔트리를 빠르게 식별합니다.

autoruns_cli.bat
batch
⚠️ 교육 목적 코드 — 방어 분석 도구
REM Autoruns CLI: 명령줄로 자동 실행 항목 분석
REM Microsoft 서명이 없는 항목만 필터링
REM 기본 스캔: 비서명 항목 필터링
autorunsc.exe -accepteula -a * -s -h -vt
REM -a * : 모든 자동 실행 위치 검사
REM -s : 비서명(unsigned) 항목만 표시
REM -h : 파일 해시 포함
REM -vt : VirusTotal 스캔 결과 포함
REM CSV 출력: SIEM 연동용
autorunsc.exe -accepteula -a * -s -c > autoruns_report.csv

#4. Sysmon Event ID 12/13 분석

📡

Sysmon 레지스트리 이벤트

Sysmon은 레지스트리 변경을 세 가지 이벤트 ID로 추적합니다: Event ID 12 — 레지스트리 키/값 생성 및 삭제. Event ID 13 — 레지스트리 값 설정 (값 변경). Event ID 14 — 레지스트리 키/값 이름 변경. Run 키 모니터링에는 특히 Event ID 13(값 설정)이 핵심입니다.

sysmon-config-runkey.xml
xml
⚠️ 교육 목적 코드 — Sysmon 설정 예시
<!-- Sysmon 설정: 레지스트리 Run 키 변경 탐지 -->
<Sysmon schemaversion="4.90">
<EventFiltering>
<!-- 레지스트리 값 설정 감시 (Event ID 13) -->
<RegistryEvent onmatch="include">
<TargetObject condition="contains">
\CurrentVersion\Run
</TargetObject>
<TargetObject condition="contains">
\CurrentVersion\RunOnce
</TargetObject>
<TargetObject condition="contains">
\Explorer\Shell Folders
</TargetObject>
</RegistryEvent>
</EventFiltering>
</Sysmon>

#5. Sigma 탐지 규칙 작성

📋

Run 키 변경 Sigma 규칙

Sigma 규칙으로 레지스트리 Run 키 변경을 탐지할 수 있습니다. Sysmon Event ID 13(RegistryValueSet)을 기반으로, TargetObject에 Run 키 경로가 포함된 이벤트를 필터링합니다. 정상 소프트웨어의 Run 키 등록을 제외하기 위해 화이트리스트 필터를 추가하는 것이 중요합니다.

run_key_modification.yml
yaml
⚠️ 교육 목적 코드 — Sigma 탐지 규칙
title: Suspicious Registry Run Key Modification
id: c7d1e5a2-9f3b-4e8d-a2c1-d5f7e3b4a6c8
status: production
level: medium
logsource:
category: registry_set
product: windows
detection:
selection:
TargetObject|contains:
- '\CurrentVersion\Run'
- '\CurrentVersion\RunOnce'
filter_trusted:
Image|startswith:
- 'C:\Program Files\'
- 'C:\Windows\System32\'
condition: selection and not filter_trusted

#7. PowerShell 기반 탐지 스크립트

🎯

자동화된 Run 키 이상 탐지

PowerShell 스크립트를 이용하여 레지스트리 Run 키의 베이스라인을 생성하고, 변경 사항을 자동으로 탐지할 수 있습니다. 파일 해시, 디지털 서명, 경로 이상 여부를 자동으로 확인하여 의심스러운 항목을 리포트합니다.

detect_suspicious_run.ps1
powershell
⚠️ 교육 목적 코드 — 방어 분석 스크립트
# 의심스러운 Run 키 항목 탐지 스크립트
# 비서명 파일, 비정상 경로 자동 검출
$suspiciousPaths = @('%TEMP%', 'C:\Users\Public',
'C:\ProgramData', '%APPDATA%')
$runPaths = @(
'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run',
'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run'
)
foreach ($path in $runPaths) {
$items = Get-ItemProperty -Path $path -EA SilentlyContinue
$items.PSObject.Properties | Where-Object {
$_.Name -notlike 'PS*'
} | ForEach-Object {
$sig = Get-AuthenticodeSignature $_.Value 2>$null
if ($sig.Status -ne 'Valid') {
Write-Warning "[ALERT] Unsigned: $($_.Name)"
}
}
}

#10. Mini Lab — Autoruns를 이용한 위협 사냥

mini-lab-2.sh

Autoruns 도구를 이용해 의심스러운 자동 실행 항목을 찾아내는 과정을 따라가 보세요.

1️⃣
Autoruns 관리자 권한으로 실행
autorunsc.exe를 관리자 권한 CMD에서 실행합니다. 전체 시스템의 자동 실행 항목을 검사하려면 관리자 권한이 필요합니다.
2️⃣
비서명 항목 필터링
Options > Hide Microsoft Entries를 활성화하고, 비서명(unsigned) 항목만 필터링합니다. 서명되지 않은 실행 파일은 의심 대상입니다.
3️⃣
의심스러운 경로 확인
%TEMP%, C:\Users\Public, AppData 등 비정상적 경로에서 실행되는 항목을 확인합니다. 정상 소프트웨어는 보통 Program Files에 위치합니다.
4️⃣
VirusTotal 스캔
의심스러운 파일의 해시를 VirusTotal에 제출합니다. Autoruns는 VT 연동 기능을 내장하고 있어 바로 스캔 결과를 확인할 수 있습니다.
5️⃣
타임라인 분석
의심 파일의 생성 시간, 수정 시간을 확인합니다. 최근에 생성된 파일이 오래된 것처럼 위장(타임스탬프 변조)되었는지 $MFT와 비교합니다.
6️⃣
보고서 생성 및 대응
발견된 의심 항목을 CSV로 내보내고, SIEM에 IoC를 등록합니다. 필요 시 해당 레지스트리 항목을 삭제하고 악성 파일을 격리합니다.

#Q. 종합 퀴즈

Q1. 공격자가 reg.exe를 이용해 Run 키에 값을 추가할 때 사용하는 핵심 명령 구문은?

💡 reg add 명령으로 Run 키에 새 값을 추가합니다. /v는 값 이름, /t REG_SZ는 문자열 타입, /d는 실행할 프로그램 경로를 지정합니다.

Q2. Sysmon Event ID 13이 탐지하는 레지스트리 이벤트는?

💡 Event ID 13은 레지스트리 값이 설정(Set)될 때 발생합니다. Run 키에 새 자동 실행 항목이 추가되면 이 이벤트가 기록됩니다.

Q3. Autoruns에서 의심 항목을 식별하는 가장 효과적인 방법은?

💡 Autoruns의 핵심 기능은 디지털 서명 확인과 VirusTotal 연동입니다. 비서명 항목 필터링 + VT 조회로 악성코드를 빠르게 식별할 수 있습니다.

Q4. 공격자가 svchost.exe를 위장할 때 가장 효과적인 탐지 방법은?

💡 정상 svchost.exe는 항상 C:\Windows\System32에서 실행됩니다. 다른 경로에서 실행되는 동일 이름 파일은 악성코드일 가능성이 높습니다.

Q5. Wow6432Node 레지스트리 경로의 목적은?

💡 64비트 Windows에서 32비트 프로그램의 레지스트리 접근은 Wow6432Node로 리다이렉션됩니다. 공격자는 이 경로를 악용하여 모니터링을 우회하기도 합니다.

Q6. Sigma 규칙에서 Run 키 변경을 탐지할 때 logsource category는?

💡 registry_set 카테고리는 Sysmon Event ID 13(RegistryValueSet)에 매핑됩니다.

Q7. 인코딩된 PowerShell 명령을 Run 키에 등록할 때 탐지 방법은?

💡 Script Block Logging은 인코딩된 명령의 디코딩된 원본을 Event ID 4104에 기록합니다.

Q8. Run 키 탐지에서 오탐을 줄이는 가장 효과적인 방법은?

💡 Sigma 규칙에서 filter_trusted 조건으로 Program Files 등 정상 경로를 제외하면 오탐을 크게 줄일 수 있습니다.
