#1. 네트워크 신뢰 관계란?

🏢 ➜ 🤝 ➜ 🏭 ➜ 🔗

"친구의 친구를 통한 침입"

네트워크 신뢰 관계(Network Trust Dependencies)란 조직 간에 설정된 VPN, 도메인 트러스트, API 연동, 서드파티 접근 권한 등을 말합니다. 공격자는 보안이 약한 파트너사를 먼저 침투한 후, 신뢰 관계를 통해 실제 타겟으로 이동합니다. SolarWinds 공급망 공격이 대표적 사례입니다.

🔑 ➜ 🏢 ➜ 🔓 ➜ 🏢

"신뢰 관계의 유형"

Active Directory 도메인 트러스트(포리스트 간 인증), VPN/IPSec 터널(사이트 간 암호화 연결), OAuth/SAML SSO(ID 제공자 위임), API 키/서비스 계정(자동화된 접근), 서드파티 원격 접근(MSSP, IT 아웃소싱) 등이 주요 유형입니다.

#2. 신뢰 관계 악용 사례

공격자는 타겟 조직의 파트너사, 공급업체, IT 서비스 제공자를 먼저 파악합니다. 보안이 약한 연결고리를 찾아 그곳을 먼저 침투한 후, 신뢰 관계를 이용해 실제 타겟에 접근합니다.

AD 도메인 트러스트를 통한 횡적 이동

Active Directory의 도메인/포리스트 트러스트는 조직 간 인증을 공유합니다. 공격자가 신뢰하는 도메인(파트너사)을 장악하면, 트러스트 관계를 통해 대상 도메인의 리소스에 접근할 수 있습니다. Golden Ticket이나 SID History Injection을 이용한 트러스트 남용이 대표적입니다.

방어: Zero Trust와 최소 권한

Zero Trust Architecture는 "아무것도 신뢰하지 않고, 항상 검증한다"는 원칙입니다. 파트너사 VPN에도 세분화된 접근 제어를 적용하고, API 키에 최소 권한을 부여하며, 서드파티 접근을 지속적으로 모니터링해야 합니다. 모든 신뢰 관계에 MFA를 강제하는 것이 핵심입니다.
