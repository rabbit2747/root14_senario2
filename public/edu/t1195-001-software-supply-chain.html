신뢰받는 소프트웨어 업데이트/패키지에 악성코드를 삽입하는 공급망 공격

#1. 개념과 원리

소프트웨어 공급망 공격이란?

소프트웨어의 개발, 빌드, 배포 파이프라인을 침투하여 정상 업데이트에 백도어를 삽입하는 공격입니다. SolarWinds 사건(2020)이 대표적이며, 정상 서명된 업데이트를 통해 18,000개 이상의 조직에 백도어가 배포되었습니다. 사용자는 신뢰하는 벤더의 공식 업데이트로 인식하여 의심 없이 설치합니다.

빌드 시스템 침투

CI/CD 파이프라인 타격으로 빌드 과정에 악성코드 주입

패키지 저장소 오염

npm, PyPI에 타이포스쿼팅 악성 패키지 등록

업데이트 서버 탈취

정상 업데이트 서버를 해킹하여 악성 업데이트 배포

#2. 공격 기법 분석

# SolarWinds 스타일 공급망 공격 시나리오
Phase 1: 벤더 빌드 서버 침투 (SUNBURST)
Phase 2: 소스코드에 백도어 삽입
Phase 3: 정상 코드 서명으로 빌드
Phase 4: 자동 업데이트로 18,000+ 조직 배포
# 피해자는 정상 업데이트로 인식

주요 공격 벡터

  • CI/CD 파이프라인: Jenkins, GitHub Actions 등 빌드 시스템 침투
  • 의존성 혼동: 내부 패키지와 동일 이름의 공개 패키지 등록
  • 코드 서명 탈취: 벤더의 코드 서명 인증서를 탈취하여 악성 빌드 서명
  • 오픈소스 기여: 정상적인 PR에 미세한 백도어 코드 삽입

#3. 탐지 및 방어 + 퀴즈

방어 전략

  • SBOM: Software Bill of Materials로 모든 구성요소 추적
  • 코드 서명 검증: 업데이트 설치 전 서명 체인 검증
  • 네트워크 세분화: 빌드 환경과 프로덕션 환경 분리
  • 의존성 잠금: lock 파일로 패키지 버전 고정 + 해시 검증
  • 제로 트러스트: 벤더 소프트웨어도 모니터링 대상으로 포함
